Master plan D5 (“normalize at publish, not in the browser”) and atlas-1 Deliverable 4. Both Shiny apps carry a per-version adapter today — two grids, mdl_seq vs mdl_key, value vs val, is_ok vs is_valid_usa, a taxon_model self-edge on one side only — each with a production bug recorded behind it. msens::app_bundle_build() (msens 0.43.0, R/app_bundle.R) already resolves every one of those quirks, with tests. This notebook is the thin publishing shell around it: build → validate → push (gated) → verify (gated), one version-independent {ver}/app/ bundle per release.

Nothing here publishes anything. The push and verification chunks are real, runnable code, gated behind APP_BUNDLE_S3=1 (unset by default) exactly like every other side-effecting step in this repo (../CLAUDE.md reproducibility rule 1) — this notebook can be rendered top to bottom, safely, with no S3 credentials and no network write of any kind.

Rendering. quarto render build_app_bundle.qmd — with or without an explicit --output — always writes its HTML BESIDE THE SOURCE (./build_app_bundle.html), never into _output/ despite this project’s _quarto.yml output-dir: _output (confirmed empirically 2026-09-21: a project-wide render like scripts/run_version.sh respects it, a single ad hoc quarto render of THIS file does not — a quirk of quarto’s single-file vs. project render path, not this notebook). The documented, ONE-TRUE command therefore always ends in a move — never render this file any other way, and never leave the moved file’s name as the version-less default:

APP_BUNDLE_VERS=v7 quarto render build_app_bundle.qmd && \
  mv -f build_app_bundle.html _output/build_app_bundle_v7.html && \
  rm -rf build_app_bundle_files

scripts/render_app_bundle.sh <ver> [ver ...] wraps exactly this (one version at a time, sequentially, in the background — see its header for why: a foreground quarto render here runs 90–190s per legacy release and longer per v8/v9, and this notebook must never be waited on in a chat turn) and is the only invocation that should be used from here on.

A cache-invalidation rule from the atlas-2 review, stated here because a publish turn must know it BEFORE it decides what to re-run: re-publishing ANY object the app reads OUTSIDE app/ — {ver}/tables/model.parquet, {ver}/serve/cell_model/** — requires rebuilding and re-publishing app/ too, because the browser caches those objects keyed on boot.built_at (OPFS), not on the object’s own URL or ETag. A tables/model.parquet re-push with no matching app/ re-push (a new built_at) leaves every already-cached client reading stale model.parquet bytes under an unchanged cache key — it will never refetch until something else bumps built_at for an unrelated reason. There is no partial-republish path for these two: either both app/ and the object move together, in the same publish turn, or neither does.

APP_BUNDLE_VERS=v7,v9 narrows a run to that set (comma-separated); unset, every version in data/versions.csv is attempted (v1, v2, v3, v4, v4b, v5, v6, v7, v7b, v8, v9 — not v3b, which is not a registered release), and a version whose release database is not on this machine is skipped, not failed (the same convention build_version_manifest.qmd’s caps_override uses: a capability this run cannot see is FALSE, never invented). Every entry is checked against BOTH the version-label shape (^v[0-9]+[a-z]?$) AND membership in data/versions.csv — round 3 (2026-09-21): shape alone let a shape-valid-but-unregistered label (e.g. v3b) silently build a bundle for a release that does not exist.

APP_BUNDLE_CELLMODEL_VERS=v7,v7b (round 3: generalized from the single, v7-only APP_BUNDLE_V7_CELLMODEL flag) additionally uploads the named version(s)’ missing serve/cell_model/ — today v7 (757 MB locally, 428 tiles) and v7b (753 MB locally, 428 tiles), both absent from S3 despite their manifest advertising cell_species_list: true (the atlas-1 “Facts” note). Default empty (nothing planned). Every entry is validated the same way as APP_BUNDLE_VERS (shape + registry) and must also be one of THIS run’s vers; each version’s plan is then checked — local tile-width (nc=3103) and one-file-per-tile gates, the exact key shape ^{ver}/serve/cell_model/tile=[0-9]+/data_0\.parquet$, and an anonymous HEAD refusing any version whose tiles already exist on S3 — before any upload, in [validate-cell-model-plan] below, which runs even when APP_BUNDLE_S3 is unset (a pure dry run: it prints the exact key list and byte total per version and writes nothing). v8 and v9 are never at risk even if mis-listed: neither has a local {ver}/cell_model/ export (their asset registry lives in the database, not a filesystem directory), so the plan refuses them with “no local source directory” before a single key is constructed.

Both APP_BUNDLE_S3 and APP_BUNDLE_V7_CELLMODEL’s replacement are strict ([app_bundle_flag()]/allow-list validation): APP_BUNDLE_S3 only exactly 1 turns it on — 0, true, false, no, anything else STOPS the render naming the variable, rather than guessing.

Two things worth saying out loud so nobody “fixes” them. First, a restricted release gets exactly the same objects under {ver}/app/ as a public one — the review gate that matters is which HOST serves them (atlas-9: the public site never renders a restricted version; the preview host does, behind Access), not what this notebook writes, so build_app_bundle.qmd never branches on access. Second, even with APP_BUNDLE_S3 and APP_BUNDLE_V7_CELLMODEL both unset — the default, publish-nothing case — a legacy-generation dry run (v1–v7b) still downloads roughly 165 MB anonymously from the public bucket (.attach_s3_legacy()’s tables/*.parquet cache, measured against v7, 2026-09-21: 13 tables, 164,894,811 bytes, dominated by cell_metric at 109 MB): reading nothing is not the same as touching nothing.

Which database. msens::sdm_db_path(ver) returns the release’s build database, and prefers sdm.duckdb over serve.duckdb whenever the former exists on this machine. That is right for v8/v9, whose native_asset table lives IN sdm.duckdb — but wrong for v1–v7b: their local sdm.duckdb has neither model_asset nor native_asset at all (verified 2026-09-21 against the real v7 release: model, not model_asset, holds only dataset/taxon/region metadata, no COG URL). model_asset is written only by backfill_versions.qmd, as a view in serve.duckdb. Opening the wrong database is not an error — app_bundle_build() runs to completion and every taxon’s merged and inputs[].assets come back silently empty, which is exactly the failure mode this contract exists to prevent everywhere else.

Three tiers, each PROBED (a view existing by name is not enough — serve.duckdb’s views embed the LOCAL paths of the machine that built them, so a copy rsynced to a laptop lists a model_asset view that then fails the moment it is queried; discovered running this notebook for real against v7):

  1. sdm_db_path(ver) (sdm.duckdb, or serve.duckdb if that is what sdm_db_path() itself falls back to) — right for v8/v9.
  2. serve.duckdb beside it, if (1) has no working asset table — right on the SERVER that built it.
  3. An ephemeral, anonymous, read-only DuckDB attached directly to this release’s published tables/*.parquet on S3 (httpfs, path-style; no credentials, no write) — right anywhere, including this laptop, for any version whose tables/*.parquet objects answer anonymously, restricted included. # does `tbl` exist AND actually return rows when queried (not just listed)?
.probe_table <- function(con, tbl) {
  if (!tbl %in% DBI::dbListTables(con)) return(FALSE)
  isTRUE(tryCatch(DBI::dbGetQuery(con, glue("SELECT count(*) n FROM {tbl} LIMIT 1"))$n >= 0,
                  error = function(e) FALSE))
}
.has_asset_tbl <- function(con) any(vapply(c("model_asset", "native_asset"), .probe_table, logical(1), con = con))

# tier 3: views over a LOCAL CACHE of the PUBLISHED tables/*.parquet -- downloaded
# once, anonymously, read-only (no S3 write, no credentials). attach_atlas() does
# the remote-view version of this for v8+'s native_asset shape, but has no
# model_asset/taxon_model view -- and a REMOTE view here was measured to be
# impractically slow: a full aggregation over `cell_metric` (unprunable row
# groups) via anonymous httpfs range reads did not finish in over an hour, where
# the equivalent LOCAL query takes seconds. `tables/` for a whole legacy release
# is under 200 MB (atlas-1 plan "Facts": v7 cell 22.7 MB + cell_metric 109 MB +
# the rest under 25 MB combined), so caching it locally costs a one-time download,
# not a redesign.
.attach_s3_legacy <- function(ver, access) {
  cache_dir <- here("_output", "app_bundle", "_s3cache", ver, "tables")
  fs::dir_create(cache_dir)
  http <- sprintf("%s/%s", base, ver)
  tbls <- c("cell", "taxon", "model", "model_asset", "metric", "cell_metric",
           "zone", "zone_cell", "zone_metric", "zone_taxon", "dataset", "taxon_model", "listing",
           "native_asset")   # r4-f: optional; a backfilled v1-v7 release carries it (else skipped, not failed)
  # round 6 (2026-09-25 review, item 5): tables app_bundle_build() cannot
  # produce a correct bundle without -- a partial cache used to be accepted
  # as long as ANY ONE table downloaded (`if (!any(got)) return(NULL)`
  # below), which could leave e.g. zone_taxon silently missing from this
  # tier's view set. Missing a required table now refuses the WHOLE tier
  # (return NULL, so app_bundle_open() falls through to its final hard
  # failure) rather than let the builder run against a connection that is
  # missing a table it needs.
  required <- c("cell", "taxon", "model", "model_asset", "zone", "zone_taxon")
  got <- vapply(tbls, function(t) {
    dest <- file.path(cache_dir, paste0(t, ".parquet"))
    if (file.exists(dest)) return(TRUE)
    # round 6 (item 5): download to a TEMP name and rename only on success --
    # the old direct-to-`dest` write left a TRUNCATED file in place on an
    # interrupted/failed download, and `if (file.exists(dest)) return(TRUE)`
    # on every LATER run then treated that truncated file as "already
    # cached", silently reusing corrupt data forever.
    tmp <- paste0(dest, ".part")
    ok <- isTRUE(tryCatch(
      utils::download.file(sprintf("%s/tables/%s.parquet", http, t), tmp,
                           mode = "wb", quiet = TRUE) == 0L,
      error = function(e) FALSE, warning = function(w) FALSE))
    ok <- ok && file.exists(tmp) && file.size(tmp) > 0
    if (ok) fs::file_move(tmp, dest) else unlink(tmp)
    ok
  }, logical(1))
  missing_required <- setdiff(required, tbls[got])
  if (length(missing_required)) {
    log_warn("{ver}: tier 3 (S3 tables/ cache) is missing required table(s) {paste(missing_required, collapse=', ')} -- refusing this tier")
    return(NULL)
  }
  if (!any(got)) return(NULL)
  con <- DBI::dbConnect(duckdb::duckdb())
  ok <- vapply(tbls[got], function(t) {
    isTRUE(tryCatch({
      DBI::dbExecute(con, glue(
        "CREATE OR REPLACE VIEW {t} AS SELECT * FROM read_parquet('{cache_dir}/{t}.parquet')"))
      .probe_table(con, t)
    }, error = function(e) FALSE))
  }, logical(1))
  if (!.has_asset_tbl(con)) { DBI::dbDisconnect(con, shutdown = TRUE); return(NULL) }
  log_warn("{ver}: cached + attached {sum(ok)}/{length(tbls)} tables from {http}/tables/ (access={access}, {cache_dir})")
  con
}

.assert_asset_ver <- function(con, ver) {
  for (tbl in c("model_asset", "native_asset")) {
    if (!tbl %in% DBI::dbListTables(con)) next
    if (!"ver" %in% DBI::dbListFields(con, tbl)) next
    vs <- DBI::dbGetQuery(con, glue("SELECT DISTINCT ver FROM {tbl}"))$ver
    if (length(vs) && !identical(as.character(vs), ver))

  }

}

.app_bundle_open_raw <- function(ver) {
  v_row  <- versions_csv |> filter(ver == !!ver)
  access <- if (nrow(v_row)) v_row$access[1] else "restricted"
  db  <- path.expand(msens::sdm_db_path(ver))
  if (file.exists(db)) {
    con <- DBI::dbConnect(duckdb::duckdb(), db, read_only = TRUE)
    if (.has_asset_tbl(con)) return(list(con = con, db = db, ok = TRUE))
    DBI::dbDisconnect(con, shutdown = TRUE)
  }
  alt <- file.path(fs::path_dir(db), "serve.duckdb")
  if (fs::path_file(db) != "serve.duckdb" && file.exists(alt)) {
    con2 <- DBI::dbConnect(duckdb::duckdb(), alt, read_only = TRUE)
    if (.has_asset_tbl(con2)) {
      log_warn("{ver}: sdm.duckdb has no working model_asset/native_asset; using serve.duckdb ({alt})")
      return(list(con = con2, db = alt, ok = TRUE))
    }
    DBI::dbDisconnect(con2, shutdown = TRUE)
  }
  con3 <- .attach_s3_legacy(ver, access)
  if (!is.null(con3)) return(list(con = con3, db = sprintf("s3 (anonymous, tables/) %s/%s", base, ver), ok = TRUE))
  if (!file.exists(db)) return(list(con = NULL, db = db, ok = FALSE))
  # round 6 (2026-09-25 review, item 3): every asset-source tier failed --
  # sdm.duckdb, serve.duckdb (if any) and the anonymous S3 tables/ cache all
  # lack a working model_asset/native_asset. This USED TO open `db` anyway and
  # return ok = TRUE ("not an error") -- which is exactly how v8/v9 could be
  # rebuilt with EVERY input asset and merged COG silently EMPTY, then pushed
  # with every gate green: R5 and the COG spot-check both correctly SKIP (not
  # fail) when there is nothing to check, because neither can tell "genuinely
  # has no assets by design" apart from "this machine failed to find the
  # database that has them". A release with no working asset source anywhere
  # is a build-environment problem, not a capability this release lacks by
  # design (contrast: a missing zone_metric table, which IS a real capability
  # gap and correctly stays a SKIP via app_bundle_gate_note()) -- so ok = FALSE
  # here, which build_one() already treats as a hard build failure the same
  # way it treats "no local release database at all".
  log_warn(paste(
    "{ver}: no database anywhere (local sdm.duckdb, local serve.duckdb, S3 tables/) carries",
    "model_asset/native_asset -- refusing to build a bundle whose merged COG urls and",
    "input assets would be silently empty"))
  list(con = NULL, db = db, ok = FALSE)
}

# asset-store M3 (default OFF): APP_BUNDLE_NATIVE_ASSET_DIR=<dir> makes the release read its pointer table from
# <dir>/<ver>/tables/native_asset.parquet (stage_publish.qmd's publish_stage/) instead of sdm.duckdb / serve.duckdb / the cache
# of the PUBLISHED tables, so the shards are built from the re-pointed registry BEFORE that table is the published one.
# A temp view shadows the real table on this connection only; nothing in the database or on S3 changes. The store objects
# the pointers name must already exist (the gates HEAD them), i.e. run it AFTER the M2 copies.
app_bundle_open <- function(ver) {
  res <- .app_bundle_open_raw(ver)
  d <- Sys.getenv("APP_BUNDLE_NATIVE_ASSET_DIR")
  if (!nzchar(d) || is.null(res$con)) return(res)
  f <- file.path(path.expand(d), ver, "tables", "native_asset.parquet")
  if (!file.exists(f)) stop(sprintf("APP_BUNDLE_NATIVE_ASSET_DIR is set but %s does not exist", f), call. = FALSE)
  DBI::dbExecute(res$con, sprintf("CREATE OR REPLACE TEMP VIEW native_asset AS SELECT * FROM read_parquet('%s')", f))
  log_warn("{ver}: native_asset is the STAGED pointer table {f} (APP_BUNDLE_NATIVE_ASSET_DIR), not the one in {res$db}")
  res
}

app/taxonomy.parquet and app/model.parquet (round 4, msens 0.43.0 @ 71aa231): both moved INTO app_bundle_build() itself — taxonomy_csv= feeds app_taxonomy() (still a curated CSV join, not a database table, but now one of the builder’s own stages, with a boot$tables digest like every other object) and app_model() writes the v8+ mdl_id -> mdl_key mapping unconditionally, returning NULL (not a failure) for v1-v7b, which have no such mapping to give. revalidate_written <- function(b) {
  if (!isTRUE(b$ok)) return(tibble())
  files <- list(
    boot  = list(path = file.path(b$dir_out, "boot.json"),  schema = "boot"),
    taxa  = list(path = file.path(b$dir_out, "taxa.json"),  schema = "taxa"))
  rows <- purrr::imap(files, function(f, nm) {
    if (!file.exists(f$path)) return(data.frame(ver = b$ver, object = nm, ok = NA, note = "not built"))
    x <- jsonlite::fromJSON(f$path, simplifyVector = FALSE)
    ok <- tryCatch({ msens::app_validate(x, f$schema); TRUE },
                    error = function(e) { message(conditionMessage(e)); FALSE })
    data.frame(ver = b$ver, object = nm, ok = ok, note = "")
  })
  for (kind in c("taxon", "alias")) {
    d <- file.path(b$dir_out, kind)
    if (!dir.exists(d)) next
    fs_ <- list.files(d, full.names = TRUE)
    bad <- 0L
    for (f in fs_) {
      x <- jsonlite::fromJSON(f, simplifyVector = FALSE)
      ok <- tryCatch({ msens::app_validate(x, kind); TRUE }, error = function(e) FALSE)
      if (!ok) bad <- bad + 1L
    }
    rows[[kind]] <- data.frame(ver = b$ver, object = sprintf("%s/*.json (n=%d)", kind, length(fs_)),
                               ok = bad == 0L, note = if (bad) sprintf("%d shard(s) FAILED", bad) else "")
  }
  bind_rows(rows)
}

digest_gate <- function(b, ver) {
  if (!isTRUE(b$ok) || is.null(b$out$tiles)) {
    app_bundle_gate_note("digest", ver, FALSE, if (!isTRUE(b$ok))
      "build did not complete" else
      "release has no cell table (no tiles were built, so no per-metric digest to check)")
    return(tibble())
  }
  app_bundle_gate_note("digest", ver, TRUE)
  con <- app_bundle_open_scoring(ver)
  on.exit(DBI::dbDisconnect(con, shutdown = TRUE), add = TRUE)
  duckdb_tune(con, file.path(tempdir(), "app_bundle_spill_digest", ver))
  keys <- b$out$tiles$metric_keys
  vc   <- msens::sdm_val_col(con, "cell_metric")
  glob <- file.path(b$dir_out, "cell", "tile=*", "data_0.parquet")   # browser-equivalent, not **/*.parquet
  bind_rows(lapply(keys, function(k) {
    kq <- DBI::dbQuoteIdentifier(con, k)
    a <- msens::hash_query(con, glue::glue(
      "SELECT cell_id, {kq} AS val FROM read_parquet('{glob}', hive_partitioning = true)
        WHERE {kq} IS NOT NULL"), cols = c("cell_id", "val"))
    # round 4 (found rendering v1 for real, 2026-09-21): v1's cell_metric has 703
    # rows whose cell_id is NOT in `cell` at all (an orphan, pre-existing in the
    # legacy database, nothing to do with this notebook) -- app_cell_tiles()
    # correctly never writes them (its own query JOINs against `cell`), so the
    # ground-truth query here must scope to the SAME cells or every legacy
    # release with an orphan cell_metric row shows a false digest mismatch. A
    # cell_metric row for a cell_id the bundle could never contain is out of
    # scope for "does the published bundle disagree with the database" -- it
    # was never a candidate to publish in the first place.
    bb <- msens::hash_query(con, glue::glue(
      "SELECT cm.cell_id, cm.{vc} AS val FROM cell_metric cm JOIN metric m USING (metric_seq)
        JOIN cell c USING (cell_id)

asset_gate <- function(b) {

  }
  app_bundle_gate_note("asset_resolution", b$ver, TRUE)

  # WRITTEN bytes: the exact taxon/*.json shards the bundle published -- an
  # input "has an asset" iff its `assets` array is non-empty, exactly what
  # card() (R/app_bundle.R) writes. Also collect the PUBLISHED taxon keys
  # (taxon/*.json's own `taxa` names) -- app_taxon_table() applies its own
  # publication filter (is_ok / valid_usa / valid_global) upstream of
  # `.app_edges()`, so a ground-truth query scoped only to
  # `taxon.mdl_seq IS NOT NULL` over-counts by exactly the taxa that HAVE a
  # merged model but are not otherwise published (27 of them on v7) --
  # verified against the real bundle: unscoped gives 12,147/10,271, scoped to
  # these published keys gives 12,120/10,247, matching the review exactly.
  taxon_dir <- file.path(b$dir_out, "taxon")

  published_keys <- character()
  for (f in list.files(taxon_dir, full.names = TRUE)) {
    d <- jsonlite::fromJSON(f, simplifyVector = FALSE)
    published_keys <- c(published_keys, names(d$taxa))
    for (taxon in d$taxa) for (inp in taxon$inputs) {
      n_bundle_total <- n_bundle_total + 1L

    }

  # `.app_assets()`) anywhere in this comparison -- only the published KEY SET
  # read directly from the written bundle above. Re-opens the SAME asset
  # source build_one() used (cheap: tier 3's per-table download is a no-op
  # once the cache from the build above already exists on disk).
  #
  # round 6 (2026-09-25 review, R5 BLOCKER): a gate that already recorded
  # "ran = TRUE" above must never silently vanish from `asset_tbl` -- the old

  # instead of returning an empty row.

      "R5: %s qualified for the asset-resolution gate but its asset source could not be re-opened (build_one() used %s) -- refusing to silently skip the M1 regression check",
      b$ver, b$con_db), call. = FALSE)

  # whatever tier this SECOND open happens to resolve to (a race on disk
  # between the two opens, or a probing-order change, would otherwise check a
  # different asset registry than the one card() actually joined against)

    stop(sprintf(
      "R5: %s's re-opened asset source (%s) differs from the one build_one() actually built the bundle from (%s) -- the gate must check the SAME data",
      b$ver, opened2$db, b$con_db), call. = FALSE)

5.10 zone_taxon.parquet integrity — independent of msens, by design

msens owns app_zone_taxon()’s internals (which of a zone type’s source tables to keep, how a duplicate resolves). This gate does not call into any of that: it reads the WRITTEN zone_taxon.parquet and boot.json bytes and checks them against each other and against the same GeoPackage geometry app_bundle_geom_keys() already resolved for the geometry-consistency gate above — three independent sources that must agree, with no msens function anywhere in the comparison. Two checks:

  1. (zone_fld, zone_value, mdl_key) is unique in zone_taxon.parquet — the same taxon, in the same zone, cannot appear twice with two different area_km2.
  2. For every drawable unit, boot$units[].keys (what the app offers), the real GeoPackage’s keys (app_bundle_geom_keys()), and the distinct zone_values actually published in zone_taxon.parquet for that field must all agree — after dropping any whole-study-area rollup (USA/FULL) from the zone_taxon.parquet side, since a rollup is scored, has no polygon, and is never in the GeoPackage or in boot$units[].keys by round 3’s own rule (found running v8/v9 for real, 2026-09-22: both list USA as a subregion_key value beside AK/AT/GA/PA, which is correct, not a defect).

              extra_in_zt     = paste(extra, collapse = ","),
              warn_missing = length(missing) > 0, stop_extra = length(extra) > 0)
  }))
  list(dup = dup_row, unit = if (is.null(unit_rows)) none_unit else unit_rows)

push_one <- function(b) {
  if (!isTRUE(b$ok)) return(invisible(NULL))
  ver <- b$ver
  before <- list_prefix(glue("{ver}/app/"))
  log_info("{ver}/app/ BEFORE push: {length(before)} object(s)")

  # round 7 (2026-09-26 review, item 4): `serve/cell_model/` syncs BEFORE the
  # `app/` loop below, so `boot.json` -- uploaded LAST within that loop --
  # stays the true final write of this version's whole push, cell_model
  # included. Its own exit status is now checked (previously ignored
  # entirely: `system2()`'s result was discarded, so a failed `aws s3 sync`
  # looked identical to a successful one), and the uploaded keys are HEADed
  # afterward to prove they actually landed -- the "already on S3" probe
  # above only ever checked `plan$keys[1]` BEFORE the sync; this checks every
  # key AFTER it.
  if (ver %in% cm_vers) {
    plan_row <- cm_plan_tbl[cm_plan_tbl$ver == ver, , drop = FALSE]
    if (nrow(plan_row) && isTRUE(plan_row$clear_to_upload[1])) {
      plan <- app_bundle_cell_model_plan(ver, dir_derived)
      app_bundle_assert_cell_model_keys(plan$keys, ver)          # exact shape, again, right before the write
      app_bundle_assert_prefix(plan$keys, ver, allow_cell_model = TRUE)  # whitelist, again
      cm_out <- system2("aws", c("s3", "sync", shQuote(plan$dir),
                                 shQuote(glue("{s3_root}/{ver}/serve/cell_model")), "--only-show-errors"),
                        stdout = TRUE, stderr = TRUE)
      if (!is.null(attr(cm_out, "status")) && attr(cm_out, "status") != 0)
        stop(glue("aws s3 sync failed for {ver}/serve/cell_model/: {paste(cm_out, collapse = '\n')}"))
      cm_check <- app_bundle_head_check(paste0(base, "/", plan$keys))
      cm_bad   <- cm_check[is.na(cm_check$status) | cm_check$status != 200L, , drop = FALSE]
      if (nrow(cm_bad))
        stop(glue(paste(
          "{ver}: serve/cell_model/ sync reported success but {nrow(cm_bad)} of {length(plan$keys)}",
          "keys do not answer 200 anonymously afterward (e.g. {cm_bad$url[1]} -> {cm_bad$status[1]})")))
      log_info("{ver}: synced serve/cell_model/ -- {length(plan$keys)} keys, {plan$bytes} bytes, all HEAD 200")
    } else {
      stop(glue(
        "{ver} is in APP_BUNDLE_CELLMODEL_VERS but this run's plan did not mark it clear_to_upload ",
        "-- refusing to sync (see the validate-cell-model-plan chunk's reason column)"))
    }
  }

  # a controlled directory walk of dir_out -- every file that exists under it,
  # nothing else -- then EVERY key derived from it still goes through the
  # whitelist guard before anything touches S3; the walk being "controlled"
  # is not itself the protection, the guard call two lines down is
  files <- list.files(b$dir_out, recursive = TRUE, full.names = TRUE)
  rels  <- fs::path_rel(files, b$dir_out)
  keys  <- glue("{ver}/app/{rels}")
  app_bundle_assert_prefix(keys, ver)                       # refuse before touching S3

  # round 6 (2026-09-25 review, item 2): `boot.json` is the Atlas's cache-
  # invalidation key -- every other object's digest is keyed under
  # `boot.tables[name].digest`, read once per session and never refetched
  # until `boot.built_at` changes (OPFS). `list.files()`'s alphabetical order
  # used to land `boot.json` BEFORE roughly 690 other objects (alias/, cell/,
  # taxon/), so a visitor mid-push could fetch the NEW boot.json (new digests)
  # alongside STILL-OLD table bytes underneath it and cache that mismatched
  # pairing under the new built_at key forever. Uploading boot.json LAST, and
  # only once every other object in this version's push has already
  # succeeded (a failure anywhere below `stop()`s this function before
  # boot.json is ever reached), means: a visitor sees either the complete OLD
  # bundle or the complete NEW one, never a mix, and a partial failure leaves
  # the OLD boot.json live on S3 -- this notebook never writes boot.json
  # unless every other object of that version's push (cell_model included,
  # now that it syncs FIRST) already landed.
  is_boot <- rels == "boot.json"
  stopifnot("exactly one boot.json must be in this version's written bundle" = sum(is_boot) == 1)
  upload_order <- c(which(!is_boot), which(is_boot))

  for (i in upload_order) {
    is_json <- grepl("\\.json$", files[i])
    src <- files[i]
    if (is_json) {
      gz <- tempfile(fileext = ".gz")
      app_bundle_gzip_file(files[i], gz)                    # byte-safe, never readLines()
      app_bundle_assert_gzip_roundtrip(gz, files[i])         # proves upload bytes == validated bytes
      src <- gz
    }
    # round 7 (item 3): boot.json is a MUTABLE cache-invalidation pointer
    # (its own bytes change what `built_at`/digests every OTHER object is
    # keyed under), never content-addressed, so it gets `no-cache` too --
    # the same convention `backfill_versions.qmd`/`build_version_manifest.qmd`
    # already apply to manifest.json
    args <- c("s3", "cp", shQuote(src), shQuote(glue("{s3_root}/{keys[i]}")),
              if (is_json) c("--content-type", shQuote("application/json"),
                             "--content-encoding", "gzip"),
              if (is_boot[i]) c("--cache-control", shQuote("no-cache")))
    out <- app_bundle_aws_retry(args)                      # a dropped connection is retried; an answer from S3 is not
    if (!is.null(attr(out, "status")) && attr(out, "status") != 0)
      stop(glue("aws s3 cp failed for {keys[i]}: {paste(out, collapse = '\n')}"))
    if (is_json) unlink(src)
  }

  after <- list_prefix(glue("{ver}/app/"))
  log_info("{ver}/app/ AFTER push: {length(after)} object(s) ({length(after) - length(before)} new)")
  invisible(list(before = before, after = after))
}

  if (!isTRUE(b$patch_ok) || is.null(b$patch_path) || !file.exists(b$patch_path)) {
    log_warn("{b$ver}: no staged manifest patch to re-stage (patch_ok={b$patch_ok})")
    return(none)
  }
  ver <- b$ver

  # item 5: the REAL first tile this run actually wrote -- read off the
  # WRITTEN local bundle, never guessed. `app/cell/tile=*/` -- browser-
  # equivalent single-file-per-tile glob, matching every other gate in this
  # notebook that reads tiles this way.
  cell_tiles <- Sys.glob(file.path(b$dir_out, "cell", "tile=*", "data_0.parquet"))
  cell_tile  <- if (length(cell_tiles)) sub(".*tile=([0-9]+).*", "\\1", cell_tiles[1]) else NULL
  # round 8: independent of cm_vers entirely -- see [app_bundle_resolve_cell_model_tile()]
  cell_model_tile <- app_bundle_resolve_cell_model_tile(ver, base, dir_derived)

    log_warn("{ver}: app_manifest_block() FAILED: {substr(conditionMessage(e), 1, 300)}")
    NULL
  })

    log_warn("{ver}: no recomputed app{{}} block -- patch left at its build-time content")
    return(list(ver = ver, ok = FALSE, cell_tile = cell_tile %||% NA_character_,
               cell_model_tile = cell_model_tile %||% NA_character_))

  # republished it since this run's build-time read
  # (app_bundle_fetch_published_manifest(), which DOES cache within a run)
  live_fresh <- app_bundle_fetch_manifest_nocache(ver, base)
  if (is.null(live_fresh))
    stop(sprintf(
      "%s: could not fetch a FRESH copy of the live manifest.json -- refusing to stage blind",
      ver), call. = FALSE)

    stop(sprintf(paste(
      "%s: the live manifest.json changed since this run's build-time read -- someone",
      "republished it mid-run; refusing to stage a patch against a stale copy"), ver), call. = FALSE)

  # re-stage the patch at the SAME path, now with the recomputed app{} block,
  # and re-run the label backfill against the (unchanged, just-proven-fresh)
  # live metrics -- same rule as the build-time patch, just not re-derived
  # from a second, independently-invented call
  p <- live_fresh; p$app <- app_block

  fs::dir_create(fs::path_dir(b$patch_path))

}

always writes its HTML BESIDE THE SOURCE (`./build_app_bundle.html`), never into `_output/`
despite this project's `_quarto.yml` `output-dir: _output` (confirmed empirically 2026-09-21: a
project-wide render like `scripts/run_version.sh` respects it, a single ad hoc `quarto render` of
THIS file does not — a quirk of quarto's single-file vs. project render path, not this notebook).
The documented, ONE-TRUE command therefore always ends in a move — never render this file any
other way, and never leave the moved file's name as the version-less default:

```sh

  mv -f build_app_bundle.html _output/build_app_bundle_v7.html && \
  rm -rf build_app_bundle_files
```

`scripts/render_app_bundle.sh <ver> [ver ...]` wraps exactly this (one version at a time,
sequentially, in the background — see its header for why: a foreground `quarto render` here runs
90–190s per legacy release and longer per v8/v9, and this notebook must never be waited on in a
chat turn) and is the only invocation that should be used from here on.

**A cache-invalidation rule from the atlas-2 review, stated here because a publish turn must know
it BEFORE it decides what to re-run**: re-publishing ANY object the app reads OUTSIDE `app/` —
`{ver}/tables/model.parquet`, `{ver}/serve/cell_model/**` — requires rebuilding and re-publishing
`app/` too, because the browser caches those objects keyed on `boot.built_at` (OPFS), not on the
object's own URL or ETag. A `tables/model.parquet` re-push with no matching `app/` re-push (a new
`built_at`) leaves every already-cached client reading stale `model.parquet` bytes under an
unchanged cache key — it will never refetch until something else bumps `built_at` for an unrelated
reason. There is no partial-republish path for these two: either both `app/` and the object move
together, in the same publish turn, or neither does.

`APP_BUNDLE_VERS=v7,v9` narrows a run to that set (comma-separated); unset, every version in
`data/versions.csv` is attempted (v1, v2, v3, v4, v4b, v5, v6, v7, v7b, v8, v9 — **not** v3b, which
is not a registered release), and a version whose release database is not on this machine is
**skipped, not failed** (the same convention `build_version_manifest.qmd`'s `caps_override`
uses: a capability this run cannot see is `FALSE`, never invented). Every entry is checked
against BOTH the version-label shape (`^v[0-9]+[a-z]?$`) AND membership in `data/versions.csv` —
round 3 (2026-09-21): shape alone let a shape-valid-but-unregistered label (e.g. `v3b`) silently
build a bundle for a release that does not exist.

`APP_BUNDLE_CELLMODEL_VERS=v7,v7b` (round 3: generalized from the single, v7-only
`APP_BUNDLE_V7_CELLMODEL` flag) additionally uploads the named version(s)' missing
`serve/cell_model/` — today v7 (757 MB locally, 428 tiles) and v7b (753 MB locally, 428 tiles),
both absent from S3 despite their manifest advertising `cell_species_list: true` (the atlas-1
"Facts" note). Default empty (nothing planned). Every entry is validated the same way as
`APP_BUNDLE_VERS` (shape + registry) and must also be one of THIS run's `vers`; each version's
plan is then checked — local tile-width (nc=3103) and one-file-per-tile gates, the exact key
shape `^{ver}/serve/cell_model/tile=[0-9]+/data_0\.parquet$`, and an anonymous HEAD refusing any
version whose tiles already exist on S3 — **before** any upload, in [validate-cell-model-plan]
below, which runs even when `APP_BUNDLE_S3` is unset (a pure dry run: it prints the exact key list
and byte total per version and writes nothing). v8 and v9 are never at risk even if
mis-listed: neither has a local `{ver}/cell_model/` export (their asset registry lives in the
database, not a filesystem directory), so the plan refuses them with "no local source directory"
before a single key is constructed.

Both `APP_BUNDLE_S3` and `APP_BUNDLE_V7_CELLMODEL`'s replacement are strict
([app_bundle_flag()]/allow-list validation): `APP_BUNDLE_S3` only exactly `1` turns it on — `0`,
`true`, `false`, `no`, anything else STOPS the render naming the variable, rather than guessing.

**Two things worth saying out loud so nobody "fixes" them.** First, a `restricted` release gets
**exactly the same objects** under `{ver}/app/` as a `public` one — the review gate that matters is
which HOST serves them (atlas-9: the public site never renders a restricted version; the preview
host does, behind Access), not what this notebook writes, so `build_app_bundle.qmd` never branches
on `access`. Second, even with `APP_BUNDLE_S3` and `APP_BUNDLE_V7_CELLMODEL` both unset — the
default, publish-nothing case — a legacy-generation dry run (v1–v7b) still downloads roughly
**165 MB anonymously** from the public bucket (`.attach_s3_legacy()`'s `tables/*.parquet` cache,
measured against v7, 2026-09-21: 13 tables, 164,894,811 bytes, dominated by `cell_metric` at 109
MB): reading nothing is not the same as touching nothing.

**Which database.** `msens::sdm_db_path(ver)` returns the release's build database, and prefers
`sdm.duckdb` over `serve.duckdb` whenever the former exists on this machine. That is right for
v8/v9, whose `native_asset` table lives IN `sdm.duckdb` — but wrong for v1–v7b: their local
`sdm.duckdb` has neither `model_asset` nor `native_asset` at all (verified 2026-09-21 against the
real v7 release: `model`, not `model_asset`, holds only dataset/taxon/region metadata, no COG
URL). `model_asset` is written only by `backfill_versions.qmd`, as a view in `serve.duckdb`. Opening
the wrong database is not an error — `app_bundle_build()` runs to completion and every taxon's
`merged` and `inputs[].assets` come back silently empty, which is exactly the failure mode this
contract exists to prevent everywhere else.

Three tiers, each PROBED (a view existing by name is not enough — `serve.duckdb`'s views embed
the LOCAL paths of the machine that built them, so a copy rsynced to a laptop lists a `model_asset`
view that then fails the moment it is queried; discovered running this notebook for real against
v7):

1. `sdm_db_path(ver)` (`sdm.duckdb`, or `serve.duckdb` if that is what `sdm_db_path()` itself
   falls back to) — right for v8/v9.
2. `serve.duckdb` beside it, if (1) has no working asset table — right on the SERVER that built it.
3. An ephemeral, **anonymous, read-only** DuckDB attached directly to this release's *published*
   `tables/*.parquet` on S3 (httpfs, path-style; no credentials, no write) — right anywhere,
   including this laptop, for any version whose `tables/*.parquet` objects answer anonymously,
   `restricted` included. Round 5 (2026-09-24 review, R2): the tier used to gate on
   `access == "public"` on the theory that a `restricted` release's objects are never
   anonymously readable — wrong for `v7b`, whose `tables/model_asset.parquet` HEADs 200
   anonymously (`RELEASE_S3_TABLES` pushes `tables/` independently of the full serve
   cutover; only the app HOST distinguishes public from restricted, per `../CLAUDE.md`'s
   pre-release review gate). This tier now attempts the download regardless of `access`
   and lets the real HTTP outcome decide: each per-table `download.file()` call already
   fails safely (`tryCatch` -> `FALSE`) on a genuine 403 (e.g. `v9`'s `tables/` today), so
   a version whose objects really are private still resolves to `NULL` here, just after a
   few fast rejected requests instead of being skipped outright.

```{r}
#| label: db-open

# does `tbl` exist AND actually return rows when queried (not just listed)?
.probe_table <- function(con, tbl) {
  if (!tbl %in% DBI::dbListTables(con)) return(FALSE)
  isTRUE(tryCatch(DBI::dbGetQuery(con, glue("SELECT count(*) n FROM {tbl} LIMIT 1"))$n >= 0,
                  error = function(e) FALSE))
}
.has_asset_tbl <- function(con) any(vapply(c("model_asset", "native_asset"), .probe_table, logical(1), con = con))

# tier 3: views over a LOCAL CACHE of the PUBLISHED tables/*.parquet -- downloaded
# once, anonymously, read-only (no S3 write, no credentials). attach_atlas() does
# the remote-view version of this for v8+'s native_asset shape, but has no
# model_asset/taxon_model view -- and a REMOTE view here was measured to be
# impractically slow: a full aggregation over `cell_metric` (unprunable row
# groups) via anonymous httpfs range reads did not finish in over an hour, where
# the equivalent LOCAL query takes seconds. `tables/` for a whole legacy release
# is under 200 MB (atlas-1 plan "Facts": v7 cell 22.7 MB + cell_metric 109 MB +
# the rest under 25 MB combined), so caching it locally costs a one-time download,
# not a redesign.
.attach_s3_legacy <- function(ver, access) {
  cache_dir <- here("_output", "app_bundle", "_s3cache", ver, "tables")
  fs::dir_create(cache_dir)
  http <- sprintf("%s/%s", base, ver)
  tbls <- c("cell", "taxon", "model", "model_asset", "metric", "cell_metric",
           "zone", "zone_cell", "zone_metric", "zone_taxon", "dataset", "taxon_model", "listing",
           "native_asset")   # r4-f: optional; a backfilled v1-v7 release carries it (else skipped, not failed)
  # round 6 (2026-09-25 review, item 5): tables app_bundle_build() cannot
  # produce a correct bundle without -- a partial cache used to be accepted
  # as long as ANY ONE table downloaded (`if (!any(got)) return(NULL)`
  # below), which could leave e.g. zone_taxon silently missing from this
  # tier's view set. Missing a required table now refuses the WHOLE tier
  # (return NULL, so app_bundle_open() falls through to its final hard
  # failure) rather than let the builder run against a connection that is
  # missing a table it needs.
  required <- c("cell", "taxon", "model", "model_asset", "zone", "zone_taxon")
  got <- vapply(tbls, function(t) {
    dest <- file.path(cache_dir, paste0(t, ".parquet"))
    if (file.exists(dest)) return(TRUE)
    # round 6 (item 5): download to a TEMP name and rename only on success --
    # the old direct-to-`dest` write left a TRUNCATED file in place on an
    # interrupted/failed download, and `if (file.exists(dest)) return(TRUE)`
    # on every LATER run then treated that truncated file as "already
    # cached", silently reusing corrupt data forever.
    tmp <- paste0(dest, ".part")
    ok <- isTRUE(tryCatch(
      utils::download.file(sprintf("%s/tables/%s.parquet", http, t), tmp,
                           mode = "wb", quiet = TRUE) == 0L,
      error = function(e) FALSE, warning = function(w) FALSE))
    ok <- ok && file.exists(tmp) && file.size(tmp) > 0
    if (ok) fs::file_move(tmp, dest) else unlink(tmp)
    ok
  }, logical(1))
  missing_required <- setdiff(required, tbls[got])
  if (length(missing_required)) {
    log_warn("{ver}: tier 3 (S3 tables/ cache) is missing required table(s) {paste(missing_required, collapse=', ')} -- refusing this tier")
    return(NULL)
  }
  if (!any(got)) return(NULL)
  con <- DBI::dbConnect(duckdb::duckdb())
  ok <- vapply(tbls[got], function(t) {
    isTRUE(tryCatch({
      DBI::dbExecute(con, glue(
        "CREATE OR REPLACE VIEW {t} AS SELECT * FROM read_parquet('{cache_dir}/{t}.parquet')"))
      .probe_table(con, t)
    }, error = function(e) FALSE))
  }, logical(1))
  if (!.has_asset_tbl(con)) { DBI::dbDisconnect(con, shutdown = TRUE); return(NULL) }
  log_warn("{ver}: cached + attached {sum(ok)}/{length(tbls)} tables from {http}/tables/ (access={access}, {cache_dir})")
  con
}

# round 6 (2026-09-25 review, item 5): E4 (msens, app_taxon_shards()) already
# stops on a `model_asset`/`native_asset` with more than one distinct `ver` --
# a NOTEBOOK-side check is still needed for the stronger claim E4 does not
# make: that the single value, when there IS one, is the version actually
# being built, not some other cached/stale file silently reused for it.
.assert_asset_ver <- function(con, ver) {
  for (tbl in c("model_asset", "native_asset")) {
    if (!tbl %in% DBI::dbListTables(con)) next
    if (!"ver" %in% DBI::dbListFields(con, tbl)) next
    vs <- DBI::dbGetQuery(con, glue("SELECT DISTINCT ver FROM {tbl}"))$ver
    if (length(vs) && !identical(as.character(vs), ver))
      stop(sprintf(
        "%s: %s.ver is %s, not '%s' -- this asset source belongs to a DIFFERENT version",
        ver, tbl, paste(shQuote(vs), collapse = ", "), ver), call. = FALSE)
  }
  invisible(TRUE)
}

.app_bundle_open_raw <- function(ver) {
  v_row  <- versions_csv |> filter(ver == !!ver)
  access <- if (nrow(v_row)) v_row$access[1] else "restricted"
  db  <- path.expand(msens::sdm_db_path(ver))

    con <- DBI::dbConnect(duckdb::duckdb(), db, read_only = TRUE)
    if (.has_asset_tbl(con)) return(list(con = con, db = db, ok = TRUE))
    DBI::dbDisconnect(con, shutdown = TRUE)
  }
  alt <- file.path(fs::path_dir(db), "serve.duckdb")
  if (fs::path_file(db) != "serve.duckdb" && file.exists(alt)) {
    con2 <- DBI::dbConnect(duckdb::duckdb(), alt, read_only = TRUE)
    if (.has_asset_tbl(con2)) {
      log_warn("{ver}: sdm.duckdb has no working model_asset/native_asset; using serve.duckdb ({alt})")
      return(list(con = con2, db = alt, ok = TRUE))
    }
    DBI::dbDisconnect(con2, shutdown = TRUE)
  }
  con3 <- .attach_s3_legacy(ver, access)
  if (!is.null(con3)) return(list(con = con3, db = sprintf("s3 (anonymous, tables/) %s/%s", base, ver), ok = TRUE))

  # round 6 (2026-09-25 review, item 3): every asset-source tier failed --
  # sdm.duckdb, serve.duckdb (if any) and the anonymous S3 tables/ cache all
  # lack a working model_asset/native_asset. This USED TO open `db` anyway and
  # return ok = TRUE ("not an error") -- which is exactly how v8/v9 could be
  # rebuilt with EVERY input asset and merged COG silently EMPTY, then pushed
  # with every gate green: R5 and the COG spot-check both correctly SKIP (not
  # fail) when there is nothing to check, because neither can tell "genuinely
  # has no assets by design" apart from "this machine failed to find the
  # database that has them". A release with no working asset source anywhere
  # is a build-environment problem, not a capability this release lacks by
  # design (contrast: a missing zone_metric table, which IS a real capability
  # gap and correctly stays a SKIP via app_bundle_gate_note()) -- so ok = FALSE
  # here, which build_one() already treats as a hard build failure the same
  # way it treats "no local release database at all".
  log_warn(paste(
    "{ver}: no database anywhere (local sdm.duckdb, local serve.duckdb, S3 tables/) carries",
    "model_asset/native_asset -- refusing to build a bundle whose merged COG urls and",
    "input assets would be silently empty"))
  list(con = NULL, db = db, ok = FALSE)
}

# asset-store M3 (default OFF): APP_BUNDLE_NATIVE_ASSET_DIR=<dir> makes the release read its pointer table from
# <dir>/<ver>/tables/native_asset.parquet (stage_publish.qmd's publish_stage/) instead of sdm.duckdb / serve.duckdb / the cache
# of the PUBLISHED tables, so the shards are built from the re-pointed registry BEFORE that table is the published one.
# A temp view shadows the real table on this connection only; nothing in the database or on S3 changes. The store objects
# the pointers name must already exist (the gates HEAD them), i.e. run it AFTER the M2 copies.
app_bundle_open <- function(ver) {
  res <- .app_bundle_open_raw(ver)
  d <- Sys.getenv("APP_BUNDLE_NATIVE_ASSET_DIR")
  if (!nzchar(d) || is.null(res$con)) return(res)
  f <- file.path(path.expand(d), ver, "tables", "native_asset.parquet")
  if (!file.exists(f)) stop(sprintf("APP_BUNDLE_NATIVE_ASSET_DIR is set but %s does not exist", f), call. = FALSE)
  DBI::dbExecute(res$con, sprintf("CREATE OR REPLACE TEMP VIEW native_asset AS SELECT * FROM read_parquet('%s')", f))
  log_warn("{ver}: native_asset is the STAGED pointer table {f} (APP_BUNDLE_NATIVE_ASSET_DIR), not the one in {res$db}")
  res
}
```

**One `msens::app_bundle_build()` call per version** — review round 1 (2026-09-21): the prior
version of this notebook composed the bundle itself (`app_boot(..., tables = list())`,
`manifest_build()` with no `zone_tiles`), which is why `boot$tables` (the OPFS invalidation key)
and `boot$units` (the drawable units) came out EMPTY on both real dry runs. `app_bundle_build()`
is the one function that wires `app_table_descriptor()`/`app_table_manifest()` into `app_boot()`
correctly; calling it directly is what makes `tables` and `units` non-empty, not a bigger
`tryCatch`. `geom_keys` — the published geometry keys `app_units()` needs to exclude
whole-study-area rollups (`USA`/`FULL`) — comes from [app_bundle_geom_keys()], which reads the
zone-set registry's own source GeoPackage rather than guessing a filename.

`app/taxonomy.parquet` and `app/model.parquet` (round 4, msens 0.43.0 @ `71aa231`): both moved INTO
`app_bundle_build()` itself — `taxonomy_csv=` feeds `app_taxonomy()` (still a curated CSV join, not
a database table, but now one of the builder's own stages, with a `boot$tables` digest like every
other object) and `app_model()` writes the v8+ `mdl_id -> mdl_key` mapping unconditionally,
returning `NULL` (not a failure) for v1-v7b, which have no such mapping to give. This notebook no
longer composes either writer itself, and `app_bundle_build()` now asserts
`names(boot$tables)` equals the Parquet objects actually on disk (`msens::app_tables_match()`,
called inside the `boot.json` stage) — the exact drift `app/taxonomy.parquet` and `model.parquet`
used to be invisible to (OPFS could never invalidate an object with no digest).

`app_bundle_build()` now isolates its own internal stages (msens 0.43.0 @ `7c6eb3a`, landed
during review round 1): `strict = TRUE` (its default) still stops the WHOLE build at the first
failing stage — right for an actual publish, wrong for this notebook's diagnostic pass — so this
notebook always passes `strict = FALSE`, matching the function's own documented "notebook's
diagnostic pass" use case: every stage that CAN complete does, `out$failed` names whichever
didn't, and the outer `tryCatch` below is only a safety net for anything upstream of `stage()`
(e.g. `app_bundle_fetch_published_manifest()` itself, or the connection open).

```{r}
  # (manifest.json AND tables/*.parquet) at the start of every build, not
  # just once ever. `app_bundle_fetch_published_manifest()`'s `if
  # (!file.exists(dest)) return(TRUE)` and `.attach_s3_legacy()`'s identical

  }

  # carries (E4, msens, already asserts single-valuedness) must be THIS
  # release, not some other version's file reused by mistake

  if (fs::dir_exists(dir_out)) fs::dir_delete(dir_out)   # clean slate every run

  # geom_keys, below) must be handed the PUBLISHED manifest.json, never a
  # rebuilt one. manifest_build()'s one-row-per-zone_set_key collapse breaks
  # a genuine tie (v2's subregion_key: two zone tables, n = 4 each) by
  # DuckDB's own row order -- non-deterministic between an installed-package
  # build and a source-tree run of the IDENTICAL commit. A missing/unreadable
  # published manifest is a hard stop: a release with no manifest cannot
  # have a bundle at all.

    ver, base, here("_output", "app_bundle", "_s3cache", ver))

      !is.null(pub_manifest) && !is.null(pub_manifest$zones) && nrow(pub_manifest$zones) > 0)

  # metrics/zone_tiles above, and the `mfst <- msens::manifest_build(...)`
  # call that used to sit here -- is now REMOVED from this notebook's render
  # path entirely, not just from app_bundle_build()'s input. Round 10 only
  # moved app_bundle_build()'s manifest= argument off of a rebuild; it left a
  # SECOND rebuild sitting right here "for the app{} patch and the id_field
  # cross-check", and that second rebuild hits the EXACT SAME tie -- v3, v4,
  # v4b, v5, v6, v7, v7b all have two subregion zone tables tied at n=4 -- so

  # cross-check below now reads `pub_manifest$id_field` (the published

  # `msens::app_manifest_block(ver, base)` -- confirmed standalone in

  # `app_capabilities()` itself), never a zones table, so it cannot trip this
  # tie at all. `app_bundle_build()`'s own return list (dir, ver, bytes,

  # derivation, the subregion cut/omit logic, the v8 AT warning): there is

  # never come from two different sources of truth. Not a hard stop the way
  # app_zone_names() is above -- bbox is OPTIONAL by schema (unlike name, which

  # the write-side gate below (n_zone_bbox_landed) is what a real regression trips.
  zone_bbox <- msens::app_zone_bbox(gpkg_for_unit, d17_type)

  # app_bundle_build() itself (as app_taxonomy(), fed by taxonomy_csv) and
  # added app_model() for the v8+ mdl_id -> mdl_key mapping -- both now get

  # via out$failed below.

  # one source zone table (v2's subregion_key: ply_subregions_2025 AND
  # ply_subregions_2026) is resolved ONCE, inside app_bundle_build(), via

  # zone_sets is a cross-check recorded in `why`. zone_sets MUST be passed

    for (w in caught_warnings) log_warn("{ver}: app_bundle_build() WARNING: {w}")

  # every drawable unit's keys must be a subset of >= 2 of its REAL geometry
  # (the assertion the original bug -- 5 subregion keys where only 4 are
  # drawable -- would have failed had it existed)
  geom_check <- if (!is.null(out) && !is.null(out$boot))
    app_bundle_assert_units_match_geometry(out$boot$units, geom_keys) else tibble()

  # round 6 (R3): the review's own correction -- the number that matters is
  # not how many name ROWS the GeoPackage happens to have (nrow(zone_names)
  # above, which passes even if every one of them fails to MATCH a real zone
  # key), it is how many names actually LANDED in the WRITTEN boot.json's
  # `zones.<unit>[i].name`. `d17_type` is this release's ONE drawable unit
  # type (D17), so `out$boot$zones[[d17_type]]` is the exact list the app
  # reads for it.
  zboot <- if (!is.null(out) && !is.null(out$boot)) out$boot$zones[[d17_type]] else NULL
  n_zone_names_expected <- length(zboot)
  n_zone_names_landed   <- if (is.null(zboot)) 0L else
    sum(vapply(zboot, function(z) !is.null(z$name) && nzchar(z$name), logical(1)))
  # R3-C3: the same "count what LANDED in the written boot.json" discipline as
  # n_zone_names_landed above, applied to bbox -- a diagnostic count only (see the
  # non-fatal app_zone_bbox() warning above), not yet a hard stopifnot gate below,
  # since this is the first release-side call publishing it against real geometry.
  n_zone_bbox_landed <- if (is.null(zboot)) 0L else
    sum(vapply(zboot, function(z) !is.null(z$bbox) && length(z$bbox) == 4, logical(1)))

  list(ver = ver, ok = !is.null(out), dir_out = dir_out, con_db = opened$db,
       pub_manifest = pub_manifest, patch_ok = !is.null(patch), patch_path = patch_path,
       label_patch_ok = label_patch_ok, label_patch_n_blank = label_patch_n_blank,
       d17_type = d17_type,
       geom_keys = geom_keys, geom_check = geom_check, out = out,
       zone_names = zone_names, n_zone_names = nrow(zone_names),

       zone_bbox = zone_bbox, n_zone_bbox = if (is.data.frame(zone_bbox)) nrow(zone_bbox) else 0L,
       n_zone_bbox_landed = n_zone_bbox_landed, n_zone_bbox_expected = n_zone_names_expected,
       warnings = caught_warnings,
       has_taxonomy = !is.null(out) && "taxonomy" %in% names(out$tables),
       has_model    = !is.null(out) && "model"    %in% names(out$tables),
       n_failed_stages = if (is.null(out)) NA_integer_ else length(out$failed),
       wall_s = as.numeric(Sys.time() - t0, units = "secs"))
}
```

```{r}
revalidate_written <- function(b) {
  if (!isTRUE(b$ok)) return(tibble())
  files <- list(
    boot  = list(path = file.path(b$dir_out, "boot.json"),  schema = "boot"),
    taxa  = list(path = file.path(b$dir_out, "taxa.json"),  schema = "taxa"))
  rows <- purrr::imap(files, function(f, nm) {
    if (!file.exists(f$path)) return(data.frame(ver = b$ver, object = nm, ok = NA, note = "not built"))
    x <- jsonlite::fromJSON(f$path, simplifyVector = FALSE)
    ok <- tryCatch({ msens::app_validate(x, f$schema); TRUE },
                    error = function(e) { message(conditionMessage(e)); FALSE })
    data.frame(ver = b$ver, object = nm, ok = ok, note = "")
  })
  for (kind in c("taxon", "alias")) {
    d <- file.path(b$dir_out, kind)
    if (!dir.exists(d)) next
    fs_ <- list.files(d, full.names = TRUE)
    bad <- 0L
    for (f in fs_) {
      x <- jsonlite::fromJSON(f, simplifyVector = FALSE)
      ok <- tryCatch({ msens::app_validate(x, kind); TRUE }, error = function(e) FALSE)
      if (!ok) bad <- bad + 1L
    }
    rows[[kind]] <- data.frame(ver = b$ver, object = sprintf("%s/*.json (n=%d)", kind, length(fs_)),
                               ok = bad == 0L, note = if (bad) sprintf("%d shard(s) FAILED", bad) else "")
  }
  bind_rows(rows)
}
```

```{r}
#| label: validate-digest

digest_gate <- function(b, ver) {
  if (!isTRUE(b$ok) || is.null(b$out$tiles)) {
    app_bundle_gate_note("digest", ver, FALSE, if (!isTRUE(b$ok))
      "build did not complete" else
      "release has no cell table (no tiles were built, so no per-metric digest to check)")
    return(tibble())
  }
  app_bundle_gate_note("digest", ver, TRUE)
  con <- app_bundle_open_scoring(ver)
  on.exit(DBI::dbDisconnect(con, shutdown = TRUE), add = TRUE)
  duckdb_tune(con, file.path(tempdir(), "app_bundle_spill_digest", ver))
  keys <- b$out$tiles$metric_keys
  vc   <- msens::sdm_val_col(con, "cell_metric")
  glob <- file.path(b$dir_out, "cell", "tile=*", "data_0.parquet")   # browser-equivalent, not **/*.parquet
  bind_rows(lapply(keys, function(k) {
    kq <- DBI::dbQuoteIdentifier(con, k)
    a <- msens::hash_query(con, glue::glue(
      "SELECT cell_id, {kq} AS val FROM read_parquet('{glob}', hive_partitioning = true)
        WHERE {kq} IS NOT NULL"), cols = c("cell_id", "val"))
    # round 4 (found rendering v1 for real, 2026-09-21): v1's cell_metric has 703
    # rows whose cell_id is NOT in `cell` at all (an orphan, pre-existing in the
    # legacy database, nothing to do with this notebook) -- app_cell_tiles()
    # correctly never writes them (its own query JOINs against `cell`), so the
    # ground-truth query here must scope to the SAME cells or every legacy
    # release with an orphan cell_metric row shows a false digest mismatch. A
    # cell_metric row for a cell_id the bundle could never contain is out of
    # scope for "does the published bundle disagree with the database" -- it
    # was never a candidate to publish in the first place.
    bb <- msens::hash_query(con, glue::glue(
      "SELECT cm.cell_id, cm.{vc} AS val FROM cell_metric cm JOIN metric m USING (metric_seq)
        JOIN cell c USING (cell_id)
        WHERE m.metric_key = {DBI::dbQuoteString(con, k)} AND cm.{vc} IS NOT NULL"),
      cols = c("cell_id", "val"))
    data.frame(ver = ver, metric_key = k, tiles = a, cell_metric = bb, ok = identical(a, bb))
  }))
}
```

```{r}
  # to rejoin it against `pub`.
  pub <- DBI::dbGetQuery(con, glue::glue("
```

### R5: asset resolution — the M1 regression check, at release level

Review round 5 (2026-09-24), item R5: the M1 bug (an INNER JOIN in `.app_assets()` keyed to the
taxon's OWN merged model id) silently dropped **every** raw input's COG — 0 of 12,120 v7 input
edges resolved an asset, and every input pill in the species app rendered struck through — while
every gate above this one stayed green, because none of them reads `inputs[].assets` at all
(`app_bundle_build()` completed, schemas validated, digests matched). This gate reads the WRITTEN
`taxon/*.json` bytes (what the fix actually produced) and compares the count against an
**independent** ground-truth query straight against `taxon_model`/`taxon`/`model_asset` — never
calling `.app_assets()`/`.app_edges()` — so a future regression in either of those internal
functions cannot make this gate agree with itself (the way it would if the gate simply called the
same function `app_bundle_build()` already calls). Scoped to `mdl_seq`-shaped releases (v1–v7b);
v8+'s `native_asset` join is a different code path the review did not find broken.

```{r}
#| label: validate-asset-resolution

asset_gate <- function(b) {
  if (!isTRUE(b$ok) || is.null(b$out$boot) || !identical(b$out$boot$id_field, "mdl_seq")) {
    app_bundle_gate_note("asset_resolution", b$ver, FALSE, if (!isTRUE(b$ok))
      "build did not complete" else if (is.null(b$out$boot)) "no boot.json" else
      "not a mdl_seq-shaped release (v8+'s native_asset join is out of scope for this gate)")
    return(tibble())
  }
  app_bundle_gate_note("asset_resolution", b$ver, TRUE)

  # WRITTEN bytes: the exact taxon/*.json shards the bundle published -- an
  # input "has an asset" iff its `assets` array is non-empty, exactly what
  # card() (R/app_bundle.R) writes. Also collect the PUBLISHED taxon keys
  # (taxon/*.json's own `taxa` names) -- app_taxon_table() applies its own
  # publication filter (is_ok / valid_usa / valid_global) upstream of
  # `.app_edges()`, so a ground-truth query scoped only to
  # `taxon.mdl_seq IS NOT NULL` over-counts by exactly the taxa that HAVE a
  # merged model but are not otherwise published (27 of them on v7) --
  # verified against the real bundle: unscoped gives 12,147/10,271, scoped to
  # these published keys gives 12,120/10,247, matching the review exactly.
  taxon_dir <- file.path(b$dir_out, "taxon")
  n_bundle_total <- 0L; n_bundle_with_asset <- 0L
  published_keys <- character()
  for (f in list.files(taxon_dir, full.names = TRUE)) {
    d <- jsonlite::fromJSON(f, simplifyVector = FALSE)
    published_keys <- c(published_keys, names(d$taxa))
    for (taxon in d$taxa) for (inp in taxon$inputs) {
      n_bundle_total <- n_bundle_total + 1L
      if (length(inp$assets)) n_bundle_with_asset <- n_bundle_with_asset + 1L
    }
  }

  # independent ground truth: raw SQL, no msens internal helper (`.app_edges()`/
  # `.app_assets()`) anywhere in this comparison -- only the published KEY SET
  # read directly from the written bundle above. Re-opens the SAME asset
  # source build_one() used (cheap: tier 3's per-table download is a no-op
  # once the cache from the build above already exists on disk).
  #
  # round 6 (2026-09-25 review, R5 BLOCKER): a gate that already recorded
  # "ran = TRUE" above must never silently vanish from `asset_tbl` -- the old
  # `if (!isTRUE(opened2$ok)) return(tibble())` let a re-open failure produce
  # ZERO rows for a qualifying release, which the downstream
  # `nrow(asset_tbl) == 0` escape hatch (meant for "no release qualified this
  # run") misreads as a pass. Both failure modes below now STOP the render
  # instead of returning an empty row.
  opened2 <- app_bundle_open(b$ver)
  if (!isTRUE(opened2$ok))
    stop(sprintf(
      "R5: %s qualified for the asset-resolution gate but its asset source could not be re-opened (build_one() used %s) -- refusing to silently skip the M1 regression check",
      b$ver, b$con_db), call. = FALSE)
  con2 <- opened2$con
  on.exit(DBI::dbDisconnect(con2, shutdown = TRUE), add = TRUE)
  # the gate must check the SAME data the bundle was actually built from, not
  # whatever tier this SECOND open happens to resolve to (a race on disk
  # between the two opens, or a probing-order change, would otherwise check a
  # different asset registry than the one card() actually joined against)
  if (!identical(opened2$db, b$con_db))
    stop(sprintf(
      "R5: %s's re-opened asset source (%s) differs from the one build_one() actually built the bundle from (%s) -- the gate must check the SAME data",
      b$ver, opened2$db, b$con_db), call. = FALSE)
  duckdb_tune(con2, file.path(tempdir(), "app_bundle_spill_r5", b$ver))
  k <- if ("ms_merge_key" %in% DBI::dbListFields(con2, "taxon")) "ms_merge_key" else "mdl_seq"
  # `temporary = TRUE`: on the server, v1-v7b's asset source is `serve.duckdb`
  # opened READ-ONLY (tier 2, app_bundle_open() above) -- a non-temporary
  # dbWriteTable() there is a `CREATE TABLE` against a read-only-attached file
  # and DuckDB refuses it ("Cannot execute statement of type CREATE ... in
  # read-only mode"). A TEMP table lives in the session's own in-memory
  # catalog regardless of how the underlying file was opened, and (being
  # session-scoped) needs no explicit drop -- `con2` is this call's own
  # ephemeral connection, torn down by the dbDisconnect on.exit() above.
  DBI::dbWriteTable(con2, "_r5_published_keys", data.frame(key = as.numeric(published_keys)),
                    temporary = TRUE, overwrite = TRUE)
  truth <- DBI::dbGetQuery(con2, glue::glue("
    WITH edges AS (
      SELECT DISTINCT tm.mdl_seq
        FROM taxon_model tm
        JOIN taxon t USING (taxon_id)
        JOIN _r5_published_keys pk ON pk.key = t.{k}
       WHERE tm.ds_key <> 'ms_merge' AND tm.mdl_seq <> t.{k}
    )
    SELECT count(*) AS n_total,
           count(*) FILTER (WHERE EXISTS (
             SELECT 1 FROM model_asset ma WHERE ma.mdl_seq = edges.mdl_seq)) AS n_with_asset
      FROM edges"))

  data.frame(ver = b$ver,
             n_bundle_total = n_bundle_total, n_bundle_with_asset = n_bundle_with_asset,
             n_truth_total = truth$n_total[1], n_truth_with_asset = truth$n_with_asset[1])
}
asset_tbl <- bind_rows(lapply(builds, asset_gate))
knitr::kable(asset_tbl, caption = paste(
  "R5 regression gate (mdl_seq releases only): WRITTEN bundle inputs-with-asset vs an",
  "INDEPENDENT ground-truth query against taxon_model/taxon/model_asset -- the M1 bug",
  "(0 assets) fails this even though every gate above it stays green"))
stopifnot(
  "R5: the bundle's inputs-with-asset count disagrees with the independent ground truth" =
    nrow(asset_tbl) == 0 ||
    all(asset_tbl$n_bundle_with_asset == asset_tbl$n_truth_with_asset &
        asset_tbl$n_bundle_total == asset_tbl$n_truth_total),

    nrow(asset_tbl) == 0 || all(asset_tbl$n_truth_with_asset == 0 | asset_tbl$n_bundle_with_asset > 0))
```

### Manifest identity — the manifest `app_bundle_build()` actually used, never a rebuilt one

Round 10 (2026-09-22): `msens::manifest_build()`'s one-row-per-`zone_set_key` collapse can lose a
genuine tie between two zone tables for the same field to DuckDB's own row order — found on v2's
`subregion_key` (`ply_subregions_2025` vs `ply_subregions_2026`, `n = 4` each): an installed
package build and a source-tree run of the SAME commit picked different tables. The fix moved to
[app_bundle_fetch_published_manifest()] — the fixed, already-published `{ver}/manifest.json`, not a
fresh rebuild — but the fix needs its own gate, or a future regression (something reintroducing a
rebuilt manifest into the `app_bundle_build()` call) would be silent again. This gate checks the
PUBLISHED manifest against the release DATABASE's own `zone_taxon.zone_tbl` column (where the
release has one: v2, v3, ..., v7b) and against `boot$units[].zone_tbl` — no rebuilt manifest
anywhere in the comparison.

```{r}
manifest_identity_gate <- function(b) {
  none <- data.frame(ver = character(), zone_fld = character(), manifest_tbl = character(),
                     n_manifest_rows = integer(), boot_zone_tbl = character(),
                     content_matches_chosen_tbl = logical(), ok = logical())
  if (!isTRUE(b$ok) || is.null(b$pub_manifest) || is.null(b$out$boot)) return(none)
  mz <- b$pub_manifest$zones
  if (is.null(mz) || !nrow(mz)) return(none)
  p <- file.path(b$dir_out, "zone_taxon.parquet")
  if (!file.exists(p)) return(none)
  zt <- arrow::read_parquet(p)
  dup_flds <- unique(mz$fld[duplicated(mz$fld)])   # requirement 1: exactly one row per fld

  con <- app_bundle_open_scoring(b$ver)
  on.exit(DBI::dbDisconnect(con, shutdown = TRUE), add = TRUE)
  has_zt_tbl_col <- "zone_taxon" %in% DBI::dbListTables(con) &&
    "zone_tbl" %in% DBI::dbListFields(con, "zone_taxon")

  units_by_type <- setNames(b$out$boot$units, vapply(b$out$boot$units, function(u) u$zone_type, ""))
  bind_rows(lapply(seq_len(nrow(mz)), function(i) {
    fld  <- mz$fld[i]; tbl <- mz$tbl[i]; type <- sub("_key$", "", fld)
    u        <- units_by_type[[type]]
    boot_tbl <- if (!is.null(u) && !is.null(u$zone_tbl)) u$zone_tbl else NA_character_
    # requirement 3: the WRITTEN zone_taxon.parquet must hold the CHOSEN
    # table's own rows -- checked as content (its zone_value SET), not just a
    # name, because the raw db zone_taxon table legitimately carries EVERY
    # candidate table's rows for a genuine tie (v2 subregion_key: both
    # ply_subregions_2025 and _2026 are really there) -- a name-only check
    # would pass no matter which table's rows actually got written.
    content_ok <- TRUE
    if (has_zt_tbl_col) {
      db_keys_for_tbl <- sort(unique(DBI::dbGetQuery(con, glue::glue(
        "SELECT DISTINCT zone_value FROM zone_taxon
          WHERE zone_fld = {DBI::dbQuoteString(con, fld)} AND zone_tbl = {DBI::dbQuoteString(con, tbl)}"))$zone_value))
      written_keys <- sort(unique(as.character(zt$zone_value[zt$zone_fld == fld])))
      # this-round fix (2026-09-22): dropped the `length(db_keys_for_tbl) > 0`
      # requirement. Under D17 a field with no drawable unit (ecoregion_key,
      # planarea_key on v3-v7b) can legitimately have ZERO zone_taxon rows
      # for its manifest-named table on BOTH sides -- v3's own scoring db has
      # no ecoregion/planarea zone_taxon rows at all, so db_keys_for_tbl and
      # written_keys are both character(0), a true match, not a defect. The
      # `>0` floor turned that into a false STOP for every one of v3-v7b's
      # undrawn fields (seeded-fault-verified below: restoring the floor
      # reproduces the exact v3 stop this round's real run hit). identical()
      # alone still catches the real defect this gate exists for: a written
      # set that differs from the manifest-named table's own content,
      # empty-vs-nonempty in either direction or a wrong non-empty set (the
      # v2 tie).
      content_ok <- identical(written_keys, db_keys_for_tbl)
    }
    ok <- !(fld %in% dup_flds) && (is.null(u) || identical(boot_tbl, tbl)) && content_ok
    data.frame(ver = b$ver, zone_fld = fld, manifest_tbl = tbl, n_manifest_rows = sum(mz$fld == fld),
               boot_zone_tbl = boot_tbl, content_matches_chosen_tbl = content_ok, ok = ok)
  }))
}
```

### `zone_taxon.parquet` integrity — independent of msens, by design

msens owns `app_zone_taxon()`'s internals (which of a zone type's source tables to keep, how a
duplicate resolves). This gate does not call into any of that: it reads the WRITTEN
`zone_taxon.parquet` and `boot.json` bytes and checks them against each other and against the
same GeoPackage geometry `app_bundle_geom_keys()` already resolved for the geometry-consistency
gate above — three independent sources that must agree, with no msens function anywhere in the
comparison. Two checks:

1. `(zone_fld, zone_value, mdl_key)` is unique in `zone_taxon.parquet` — the same taxon, in the
   same zone, cannot appear twice with two different `area_km2`.
2. For every drawable unit, `boot$units[].keys` (what the app offers), the real GeoPackage's keys
   (`app_bundle_geom_keys()`), and the distinct `zone_value`s actually published in
   `zone_taxon.parquet` for that field must all agree — after dropping any whole-study-area
   rollup (`USA`/`FULL`) from the `zone_taxon.parquet` side, since a rollup is scored, has no
   polygon, and is never in the GeoPackage or in `boot$units[].keys` by round 3's own rule (found
   running v8/v9 for real, 2026-09-22: both list `USA` as a `subregion_key` value beside
   `AK`/`AT`/`GA`/`PA`, which is correct, not a defect).

**Proved RED on today's v2 bundle** (built on msens 0.43.0 @ `71aa231`, before its zone-table fix
landed): v2's source has two zone tables for `subregion_key`
(`ply_subregions_2025`/`ply_subregions_2026`); `app_zone_taxon()` merged rows from both instead of
choosing one, so 13,077 `(zone_fld, zone_value, mdl_key)` triples are duplicated with two different
`area_km2` values each (e.g. `subregion_key`/`AK`/mdl_key `1` appears twice) — verified directly
against `_output/app_bundle/v2/zone_taxon.parquet`: `n_dup_groups = 13077`, `n_dup_rows = 13077`.

```{r}
#| label: validate-zone-taxon-integrity

zone_taxon_integrity_gate <- function(b) {
  none_dup  <- data.frame(ver = character(), n_dup_groups = integer(), n_dup_rows = integer(),
                          zone_taxon_unique = logical())
  none_unit <- data.frame(ver = character(), zone_type = character(),
                          n_boot_keys = integer(), n_geom_keys = integer(), n_zt_keys = integer(),
                          missing_from_zt = character(), extra_in_zt = character(),
                          warn_missing = logical(), stop_extra = logical())
  if (!isTRUE(b$ok) || is.null(b$out$boot)) return(list(dup = none_dup, unit = none_unit))
  p <- file.path(b$dir_out, "zone_taxon.parquet")
  if (!file.exists(p)) return(list(dup = none_dup, unit = none_unit))
  zt <- arrow::read_parquet(p)

  dupg <- zt |> dplyr::count(zone_fld, zone_value, mdl_key) |> dplyr::filter(n > 1)
  dup_row <- data.frame(ver = b$ver, n_dup_groups = nrow(dupg),
                        n_dup_rows = if (nrow(dupg)) sum(dupg$n - 1) else 0L,
                        zone_taxon_unique = nrow(dupg) == 0)

  # round 9 (msens 0.43.0 @ 9e66946, "the geometry check asks about units"):
  # a scored, published unit key can legitimately have ZERO zone_taxon rows
  # (v8 subregion AT: scored, 52,674 cells, but no species-per-zone rows --
  # boot$zones[unit][].n_taxa == 0, a gap in the release's OWN table, not an
  # error msens invents around). That direction -- a boot key missing from
  # zone_taxon -- is a WARNING here, never a stop. The OTHER direction -- a
  # zone_taxon key that ISN'T a boot key at all -- is still a real integrity
  # violation (data for a key that was never even a valid unit) and stays a
  # hard stop. A key with no polygon (USA/FULL rollups) is dropped from the
  # zone_taxon side before either comparison, same as before.
  units <- b$out$boot$units
  unit_rows <- bind_rows(lapply(units, function(u) {
    fld       <- paste0(u$zone_type, "_key")
    boot_keys <- sort(unique(as.character(unlist(u$keys))))
```

### Anonymous COG spot-check (species assets) — SKIPS, with a reason, when a release has no merged COG

Formalizes what was previously an ad-hoc post-render `curl` script into a real notebook gate.
Samples ALL `sp_cat == "turtle"` taxa (a handful, always checked in full) plus up to 300 other
taxa, from the WRITTEN `taxon/*.json` shards ([app_bundle_cog_sample()]) — the exact bytes an app
would fetch, not a query against the database — then HEADs each URL anonymously, in parallel
([app_bundle_head_check()]). `xargs -P`'s workers finish in an unpredictable order, so each result
line carries both its URL and its status code and is re-associated by CONTENT, never by position —
a naive positional read would silently pair the wrong status with the wrong URL under load. A
release whose written bundle has no taxon with a merged COG (no asset registry — `model_asset` /
`native_asset` — was reachable at build time; see [app_bundle_open()]'s 3-tier probe above) SKIPS
this gate with that reason rather than failing it: there is nothing to check, which is not the same
as everything being broken.

```{r}
    return(none(reason))

  # missing" while four concurrent Playwright suites saturated the laptop's
```

## Budgets (bytes vs the subplan's per-object budgets — FAILS the render, not just flags)

```{r}
budgets_spec <- app_bundle_budgets()

.budget_row <- function(object, sizes, kind, budget_bytes) {
  if (!length(sizes)) return(NULL)
  data.frame(object = object, kind = kind, n = length(sizes),
             bytes_p50 = as.integer(round(median(sizes))),
             bytes_p90 = as.integer(round(quantile(sizes, 0.9))),
             bytes_max = as.integer(max(sizes)),
             budget_bytes = as.integer(budget_bytes),
             n_over_budget = sum(sizes > budget_bytes))
}
.sizes_for <- function(dir_out, object, kind) {
  gz_of <- function(p) { tmp <- tempfile(fileext = ".gz"); app_bundle_gzip_file(p, tmp)
                         sz <- file.size(tmp); unlink(tmp); sz }
  if (object %in% c("boot.json", "taxa.json")) {
    p <- file.path(dir_out, object)
    if (!file.exists(p)) return(numeric())
    if (kind == "gzip") gz_of(p) else file.size(p)
  } else if (object %in% c("taxon/*.json", "alias/*.json")) {
    d <- file.path(dir_out, sub("/\\*\\.json$", "", object))
    if (!dir.exists(d)) return(numeric())
    fs_ <- list.files(d, full.names = TRUE)
    if (kind == "gzip") vapply(fs_, gz_of, numeric(1)) else file.size(fs_)
  } else if (object == "cell/tile=*/data_0.parquet") {
    fs_ <- Sys.glob(file.path(dir_out, "cell", "tile=*", "data_0.parquet"))  # browser-equivalent
    file.size(fs_)
  } else {  # taxon.parquet, taxonomy.parquet, zone_taxon.parquet
    p <- file.path(dir_out, object)
    if (!file.exists(p)) numeric() else file.size(p)
  }
}

budgets_one <- function(b) {

    spec <- budgets_spec[i, ]

  })
  out <- bind_rows(Filter(Negate(is.null), rows))
  if (nrow(out)) out$ver <- b$ver
  out
}
```

```{r}
s3_root <- "s3://oceanmetrics.io-public/marine-atlas"

list_prefix <- function(prefix) {
  out <- system2("aws", c("s3", "ls", shQuote(glue("{s3_root}/{prefix}")), "--recursive"),
                stdout = TRUE, stderr = TRUE)
  if (!is.null(attr(out, "status")) && attr(out, "status") != 0) character(0) else out
}

push_one <- function(b) {
  if (!isTRUE(b$ok)) return(invisible(NULL))
  ver <- b$ver
  before <- list_prefix(glue("{ver}/app/"))
  log_info("{ver}/app/ BEFORE push: {length(before)} object(s)")

  # round 7 (2026-09-26 review, item 4): `serve/cell_model/` syncs BEFORE the
  # `app/` loop below, so `boot.json` -- uploaded LAST within that loop --
  # stays the true final write of this version's whole push, cell_model
  # included. Its own exit status is now checked (previously ignored
  # entirely: `system2()`'s result was discarded, so a failed `aws s3 sync`
  # looked identical to a successful one), and the uploaded keys are HEADed
  # afterward to prove they actually landed -- the "already on S3" probe
  # above only ever checked `plan$keys[1]` BEFORE the sync; this checks every
  # key AFTER it.
  if (ver %in% cm_vers) {
    plan_row <- cm_plan_tbl[cm_plan_tbl$ver == ver, , drop = FALSE]
    if (nrow(plan_row) && isTRUE(plan_row$clear_to_upload[1])) {
      plan <- app_bundle_cell_model_plan(ver, dir_derived)
      app_bundle_assert_cell_model_keys(plan$keys, ver)          # exact shape, again, right before the write
      app_bundle_assert_prefix(plan$keys, ver, allow_cell_model = TRUE)  # whitelist, again
      cm_out <- system2("aws", c("s3", "sync", shQuote(plan$dir),
                                 shQuote(glue("{s3_root}/{ver}/serve/cell_model")), "--only-show-errors"),
                        stdout = TRUE, stderr = TRUE)
      if (!is.null(attr(cm_out, "status")) && attr(cm_out, "status") != 0)
        stop(glue("aws s3 sync failed for {ver}/serve/cell_model/: {paste(cm_out, collapse = '\n')}"))
      cm_check <- app_bundle_head_check(paste0(base, "/", plan$keys))
      cm_bad   <- cm_check[is.na(cm_check$status) | cm_check$status != 200L, , drop = FALSE]
      if (nrow(cm_bad))
        stop(glue(paste(
          "{ver}: serve/cell_model/ sync reported success but {nrow(cm_bad)} of {length(plan$keys)}",
          "keys do not answer 200 anonymously afterward (e.g. {cm_bad$url[1]} -> {cm_bad$status[1]})")))
      log_info("{ver}: synced serve/cell_model/ -- {length(plan$keys)} keys, {plan$bytes} bytes, all HEAD 200")
    } else {
      stop(glue(
        "{ver} is in APP_BUNDLE_CELLMODEL_VERS but this run's plan did not mark it clear_to_upload ",
        "-- refusing to sync (see the validate-cell-model-plan chunk's reason column)"))
    }
  }

  # a controlled directory walk of dir_out -- every file that exists under it,
  # nothing else -- then EVERY key derived from it still goes through the
  # whitelist guard before anything touches S3; the walk being "controlled"
  # is not itself the protection, the guard call two lines down is
  files <- list.files(b$dir_out, recursive = TRUE, full.names = TRUE)
  rels  <- fs::path_rel(files, b$dir_out)
  keys  <- glue("{ver}/app/{rels}")
  app_bundle_assert_prefix(keys, ver)                       # refuse before touching S3

  # round 6 (2026-09-25 review, item 2): `boot.json` is the Atlas's cache-
  # invalidation key -- every other object's digest is keyed under
  # `boot.tables[name].digest`, read once per session and never refetched
  # until `boot.built_at` changes (OPFS). `list.files()`'s alphabetical order
  # used to land `boot.json` BEFORE roughly 690 other objects (alias/, cell/,
  # taxon/), so a visitor mid-push could fetch the NEW boot.json (new digests)
  # alongside STILL-OLD table bytes underneath it and cache that mismatched
  # pairing under the new built_at key forever. Uploading boot.json LAST, and
  # only once every other object in this version's push has already
  # succeeded (a failure anywhere below `stop()`s this function before
  # boot.json is ever reached), means: a visitor sees either the complete OLD
  # bundle or the complete NEW one, never a mix, and a partial failure leaves
  # the OLD boot.json live on S3 -- this notebook never writes boot.json
  # unless every other object of that version's push (cell_model included,
  # now that it syncs FIRST) already landed.
  is_boot <- rels == "boot.json"
  stopifnot("exactly one boot.json must be in this version's written bundle" = sum(is_boot) == 1)
  upload_order <- c(which(!is_boot), which(is_boot))

  for (i in upload_order) {
    is_json <- grepl("\\.json$", files[i])
    src <- files[i]
    if (is_json) {
      gz <- tempfile(fileext = ".gz")
      app_bundle_gzip_file(files[i], gz)                    # byte-safe, never readLines()
      app_bundle_assert_gzip_roundtrip(gz, files[i])         # proves upload bytes == validated bytes
      src <- gz
    }
    # round 7 (item 3): boot.json is a MUTABLE cache-invalidation pointer
    # (its own bytes change what `built_at`/digests every OTHER object is
    # keyed under), never content-addressed, so it gets `no-cache` too --
    # the same convention `backfill_versions.qmd`/`build_version_manifest.qmd`
    # already apply to manifest.json
    args <- c("s3", "cp", shQuote(src), shQuote(glue("{s3_root}/{keys[i]}")),
              if (is_json) c("--content-type", shQuote("application/json"),
                             "--content-encoding", "gzip"),
              if (is_boot[i]) c("--cache-control", shQuote("no-cache")))
    out <- app_bundle_aws_retry(args)                      # a dropped connection is retried; an answer from S3 is not
    if (!is.null(attr(out, "status")) && attr(out, "status") != 0)
      stop(glue("aws s3 cp failed for {keys[i]}: {paste(out, collapse = '\n')}"))
    if (is_json) unlink(src)
  }

  after <- list_prefix(glue("{ver}/app/"))
  log_info("{ver}/app/ AFTER push: {length(after)} object(s) ({length(after) - length(before)} new)")
  invisible(list(before = before, after = after))
}
push_out <- purrr::map(builds, push_one)
```

## Stage the manifest patch (always runs — a real dry run, same discipline as `validate-cell-model-plan`)

Round 6 (2026-09-25 review, item 4), extended round 7 (items 2, 3, 5) and round 8 (2026-09-25). Every
earlier round built and validated `patch` (the live `{ver}/manifest.json` plus
[app_manifest_block()]'s `app{}` block and the R4 label backfill) at BUILD time — before anything
from this run existed on S3, with `msens::app_capabilities()` probing the never-real `tile=0`
placeholder. This chunk RE-stages that patch, correctly, and **always runs, `APP_BUNDLE_S3` or
not** — round 8's own bug is why: the first real publish of v7 pushed `cell_model: FALSE` even
though `v7/serve/cell_model/tile=19/data_0.parquet` was genuinely on S3, and the only way to catch
that kind of mistake before a push is to make the SAME staging step run on every dry run too, not
only inside the `do_s3`-gated push.

1. **Recomputes `app{}`** from the REAL tiles on disk/S3 right now — `msens::app_capabilities()`'s
   `cell_tile`/`cell_model_tile` arguments (msens 0.44.1) probe the real first tile instead of
   `tile=0`. `cell_model_tile` is resolved by [app_bundle_resolve_cell_model_tile()], independent of
   whether THIS run synced `serve/cell_model/` at all (`APP_BUNDLE_CELLMODEL_VERS`) — it HEADs the
   local plan's own first key anonymously, so a version whose cell_model was uploaded in an EARLIER
   run still correctly resolves `cell_model: true` (the round 8 bug: the OLD logic only ever looked
   when `ver %in% cm_vers`, true for the one sync run and false for every run since).
2. **Re-fetches the live manifest FRESH** (never the build-time cache) and asserts it is
   `identical()` to `b$pub_manifest` — if it differs, someone republished `{ver}/manifest.json`
   between this run's build and this stage, and staging a patch against a now-stale copy would
   silently discard whatever changed it. Stops rather than guess.
3. Re-stages the patch at the SAME `patch_path` with the recomputed `app{}` block and re-runs
   [app_bundle_assert_manifest_patch_diff()] against the FRESH live manifest (never the build-time
   one) — any change other than `app{}` plus blank-to-non-blank labels still stops the render.

Nothing here touches S3 for a write — HEAD probes and a `GET` of the live `manifest.json` are the
only network calls, exactly the same anonymous-read discipline `validate-cell-model-plan`'s
already-on-S3 probe and the COG spot-check use.

```{r}
#| label: stage-manifest-patch

stage_manifest_patch_one <- function(b) {
  none <- list(ver = b$ver, ok = FALSE, cell_tile = NA_character_, cell_model_tile = NA_character_)
  if (!isTRUE(b$ok)) return(none)
  if (!isTRUE(b$patch_ok) || is.null(b$patch_path) || !file.exists(b$patch_path)) {
    log_warn("{b$ver}: no staged manifest patch to re-stage (patch_ok={b$patch_ok})")
    return(none)
  }
  ver <- b$ver

  # item 5: the REAL first tile this run actually wrote -- read off the
  # WRITTEN local bundle, never guessed. `app/cell/tile=*/` -- browser-
  # equivalent single-file-per-tile glob, matching every other gate in this
  # notebook that reads tiles this way.
  cell_tiles <- Sys.glob(file.path(b$dir_out, "cell", "tile=*", "data_0.parquet"))
  cell_tile  <- if (length(cell_tiles)) sub(".*tile=([0-9]+).*", "\\1", cell_tiles[1]) else NULL
  # round 8: independent of cm_vers entirely -- see [app_bundle_resolve_cell_model_tile()]
  cell_model_tile <- app_bundle_resolve_cell_model_tile(ver, base, dir_derived)
  caps <- msens::app_capabilities(ver, base, cell_tile = cell_tile, cell_model_tile = cell_model_tile)
  app_block <- tryCatch(msens::app_manifest_block(ver, base, capabilities = caps), error = function(e) {
    log_warn("{ver}: app_manifest_block() FAILED: {substr(conditionMessage(e), 1, 300)}")
    NULL
  })
  if (is.null(app_block)) {
    log_warn("{ver}: no recomputed app{{}} block -- patch left at its build-time content")
    return(list(ver = ver, ok = FALSE, cell_tile = cell_tile %||% NA_character_,
               cell_model_tile = cell_model_tile %||% NA_character_))
  }

  # item 2: a FRESH, never-cached read of the live manifest -- proves nothing
  # republished it since this run's build-time read
  # (app_bundle_fetch_published_manifest(), which DOES cache within a run)
  live_fresh <- app_bundle_fetch_manifest_nocache(ver, base)
  if (is.null(live_fresh))
    stop(sprintf(
      "%s: could not fetch a FRESH copy of the live manifest.json -- refusing to stage blind",
      ver), call. = FALSE)
  if (!identical(live_fresh, b$pub_manifest))
    stop(sprintf(paste(
      "%s: the live manifest.json changed since this run's build-time read -- someone",
      "republished it mid-run; refusing to stage a patch against a stale copy"), ver), call. = FALSE)

  # re-stage the patch at the SAME path, now with the recomputed app{} block,
  # and re-run the label backfill against the (unchanged, just-proven-fresh)
  # live metrics -- same rule as the build-time patch, just not re-derived
  # from a second, independently-invented call
  p <- live_fresh; p$app <- app_block
  p <- msens::manifest_labels_backfill(p)
  fs::dir_create(fs::path_dir(b$patch_path))
  jsonlite::write_json(p, b$patch_path, auto_unbox = TRUE, pretty = TRUE, null = "null")

  staged <- jsonlite::fromJSON(b$patch_path, simplifyVector = TRUE)
  app_bundle_assert_manifest_patch_diff(live_fresh, staged, ver)   # stops on anything unexpected

  list(ver = ver, ok = TRUE, cell_tile = cell_tile %||% NA_character_,
       cell_model_tile = cell_model_tile %||% NA_character_)
}
stage_tbl <- bind_rows(lapply(builds, stage_manifest_patch_one))
knitr::kable(stage_tbl, caption = paste(
  "Manifest patch re-staged (always, dry run or not): cell_tile/cell_model_tile actually resolved,",
  "and whether the re-stage + diff-guard succeeded"))
stopifnot(
  # every row here already has b$ok == TRUE -- the earlier "Build" chunk's own
  # stopifnot(all(build_tbl$ok)) would already have stopped the render otherwise
  "the manifest patch failed to re-stage for at least one version" =
    nrow(stage_tbl) == 0 || all(stage_tbl$ok))
```

## Push the manifest patch (`APP_BUNDLE_S3=1` only, AFTER the bundle objects above)

The push itself is now trivial: [stage-manifest-patch] above already produced a validated,
up-to-date `patch_path` on disk for every version, `do_s3` or not — this chunk's only job is the
actual `aws s3 cp`.

`{ver}/manifest.json` is published as **plain JSON, not gzip** — matching the live manifest's own
encoding (verified: `Content-Type: application/json`, no `Content-Encoding` header on every
published manifest.json checked while building this notebook), unlike every object under
`{ver}/app/`, which this notebook always gzips. Pushing it gzipped would silently break any
existing consumer that fetches `manifest.json` without requesting/decoding gzip — including this
notebook's own [app_bundle_fetch_published_manifest()], a plain `download.file()` with no
decompression step. `--cache-control no-cache`: `manifest.json` is a MUTABLE pointer (the same
convention `backfill_versions.qmd`/`build_version_manifest.qmd` already use), never a
content-addressed object, so a CDN/browser must always revalidate it.

```{r}
#| label: push-manifest
#| eval: !expr do_s3

push_manifest_one <- function(b) {
  st <- stage_tbl[stage_tbl$ver == b$ver, , drop = FALSE]
  if (!isTRUE(b$ok) || !nrow(st) || !isTRUE(st$ok[1])) {
    log_warn("{b$ver}: manifest patch did not stage successfully -- skipping manifest push")
    return(invisible(NULL))
  }
  ver <- b$ver
  key <- sprintf("%s/manifest.json", ver)
  app_bundle_assert_prefix(key, ver, allow_manifest = TRUE)     # whitelist: ONLY this exact key

  args <- c("s3", "cp", shQuote(b$patch_path), shQuote(glue("{s3_root}/{key}")),
            "--content-type", shQuote("application/json"),      # plain JSON, matching the live object
            "--cache-control", shQuote("no-cache"))
  out <- app_bundle_aws_retry(args)
  if (!is.null(attr(out, "status")) && attr(out, "status") != 0)
    stop(glue("aws s3 cp failed for {key}: {paste(out, collapse = '\n')}"))
  log_info("{ver}: pushed {key} (cell_tile={st$cell_tile[1]}, cell_model_tile={st$cell_model_tile[1]})")
  invisible(key)
}
```

as the browser will fetch it: 200, `content-encoding: gzip` on every JSON object, path-style URL,

```{r}
verify_one <- function(b) {
  if (!isTRUE(b$ok)) return(tibble())
  ver <- b$ver
  files <- list.files(b$dir_out, recursive = TRUE, full.names = TRUE)
  rels  <- fs::path_rel(files, b$dir_out)
  urls  <- glue("{base}/{ver}/app/{rels}")
  purrr::map_dfr(seq_along(urls), function(i) {
    r <- tryCatch(
      httr2::req_perform(httr2::req_error(httr2::req_method(httr2::request(urls[i]), "HEAD"),
                                          is_error = function(resp) FALSE)),
      error = function(e) NULL)
    is_json <- grepl("\\.json$", files[i])
    data.frame(
      ver = ver, key = rels[i],
      status = if (is.null(r)) NA_integer_ else httr2::resp_status(r),
      path_style = grepl("^https://s3\\.[a-z0-9-]+\\.amazonaws\\.com/", urls[i]),
      gzip_ok = if (is.null(r) || !is_json) NA else
        identical(httr2::resp_header(r, "content-encoding"), "gzip"),
      bytes = if (is.null(r)) NA_integer_ else
        suppressWarnings(as.integer(httr2::resp_header(r, "content-length"))))
  })
}
```
