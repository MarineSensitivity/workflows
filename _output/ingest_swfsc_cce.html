NOAA Southwest Fisheries Science Center (SWFSC) habitat-based density models for 13 cetacean species in the California Current Ecosystem (CCE), summer–fall (Becker et al. 2020), put on the MarineSensitivity global 0.05° cell grid (global05) so each species can be previewed on its own.

This is a preview ingest and stays out of every scoring version. Nothing here is merged, scored, registered or released. The outputs live outside the version directories, in {dir_derived}/preview/swfsc_cce/. How a density surface should enter the [0,100] merge is the open question in compare_density_methods, and it is not answered here. The values stay in animals km⁻².

1 Source

The models come from line-transect ship surveys by SWFSC in the CCE, nine summer–fall surveys between 1991 and 2018. Habitat-based density models were fitted to those surveys using dynamic ocean covariates from a model calibrated to the CCE. The authors averaged the predictions over the survey seasons and assigned them to a 0.1° grid, clipped at the coast and the study-area edge. The delivery is an Esri file geodatabase with one layer per species, holding 12,257 cells each. Every cell carries DENSITY (animals km⁻²), UNCERTAINTY, AREA_SQKM and ABUNDANCE (DENSITY × AREA_SQKM).

Two points from the InPort metadata (item 64349 and its attribute entity 64350) matter here:

  • UNCERTAINTY is a coefficient of variation. The attribute definition (quoted in Credits and use constraints) calls it “Numerical uncertainty value (CV)”, with -99999 where no estimate exists. No layer here uses that sentinel. The values run from 0.12 to 6.4, and a CV above 1 is legitimate for a sparse species.
  • AREA_SQKM is the true ellipsoidal area of each clipped cell. The source chunk shows that it matches sf::st_area() on WGS84 to within 0.1 %. Because the 0.05° cell areas below are also ellipsoidal, the abundance check can be held to 1 %.

The record’s abstract also lists sperm whale and a small-beaked-whale guild (Mesoplodon spp. and Cuvier’s beaked whale). Those surfaces are not in this geodatabase, which holds 13 layers.

2 What this notebook does

  1. Reads the 13 layers and asserts what it relies on: 12,257 cells per layer, identical geometry across layers, one species and one season per layer, and ABUNDANCE = DENSITY × AREA_SQKM.
  2. Resolves each SPECIES_2 to a WoRMS AphiaID from the pipeline’s own WoRMS snapshot (spp.duckdb worms), with a live worrms cross-check when the network is available.
  3. Area-weighted regrid. For each 0.05° cell c: \(\hat d_c = \sum_p d_p\,A(p \cap c) \,/\, \sum_p A(p \cap c)\). Here \(A\) is the exact overlap area in km², computed as the exactextractr coverage fraction times the cell’s WGS84 ellipsoidal area, which depends on latitude. The same weighting gives the CV and the covered fraction of each cell. The rule lives in msens (poly_cell_overlap(), cells_area_mean(), msens ≥ 0.59.0), and test-ingest.R checks it against a synthetic fixture. The polygon-cell weights are computed once, because all 13 layers share the same geometry.
  4. Checks every species: the regridded abundance \(\sum_c \hat d_c \cdot \text{covered km}^2\) is within 1 % of \(\sum\) ABUNDANCE, no output cell lies outside the source extent, and every density is ≥ 0.
  5. Writes one 2-band Float32 COG per species (density, CV), aligned to the grid, plus the long Parquet and the models.csv model table. It writes DONE last.
NoteThe CV band is an approximation

An area-weighted mean is right for a density, which is intensive: the regridded abundance equals the source abundance. It is not right for a CV, because the CVs of the parts of a cell do not average linearly. The CV of a mixed cell’s density would need the covariance between its parts, which the delivery does not carry. Band 2 is therefore an area-weighted average of the source CVs. It is exact only where an output cell lies inside a single source cell, and the regrid section counts how many cells do.

6 Taxa → WoRMS

Each delivered name (SPECIES_2) is matched exactly against the pipeline’s WoRMS snapshot. Where a name has several WoRMS records (homonyms and synonym records), the rule picks one in this order:

  1. the record that is itself accepted;
  2. otherwise, a synonym whose accepted taxon is accepted and in the same genus;
  3. otherwise, a synonym whose accepted taxon is accepted.

The render stops if more than one record ties at the top, or if any accepted target is not itself accepted.

11 of the 13 delivered names are accepted in WoRMS, and 2 are synonyms:

  • Delphinus capensis, the long-beaked common dolphin, is unaccepted in WoRMS and placed under Delphinus delphis. The InPort abstract itself calls this population Delphinus delphis bairdii, but WoRMS lists that subspecies as nomen dubium, so no accepted WoRMS taxon is specific to the CCE long-beaked form.
  • Lagenorhynchus obliquidens, the Pacific white-sided dolphin, is a junior objective synonym of Sagmatias obliquidens.

Key choice. mdl_key and the file names use the AphiaID of the name as delivered (worms_id), not the accepted one. A raw model key identifies the source’s own species, in the same way that AquaMaps keys use its species code. Using the accepted id would collide for the two Delphinus layers: Long beaked common dolphin and Short beaked common dolphin share accepted AphiaID 137094. The accepted id is kept in worms_id_accepted. A per-taxon merge would fold both layers into one D. delphis surface, and that is a decision for whoever promotes this dataset.

9 Write COGs

Each species gets one COG, cog/cce_<worms_id>_summer-fall.tif. Band 1 is density (animals km⁻²) and band 2 is cv. Both are Float32 with nodata −9999 outside the modelled cells, DEFLATE-compressed with the floating-point predictor, and in 256 × 256 blocks. There are no internal overviews, because titiler decimates from full resolution. The window is cut from the cell-id raster by row and column, so its origin and pixel size are the grid’s own, including the ~5 × 10⁻⁶° float drift. Each output pixel is a global05 cell.

## Source

The models come from line-transect ship surveys by SWFSC in the CCE, nine summer–fall surveys
between 1991 and 2018. Habitat-based density models were fitted to those surveys using dynamic ocean
covariates from a model calibrated to the CCE. The authors averaged the predictions over the survey
seasons and assigned them to a 0.1° grid, clipped at the coast and the study-area edge. The delivery is
an Esri file geodatabase with one layer per species, holding 12,257 cells each. Every cell carries
`DENSITY` (animals km⁻²), `UNCERTAINTY`, `AREA_SQKM` and `ABUNDANCE` (`DENSITY × AREA_SQKM`).

Two points from the InPort metadata ([item 64349](https://www.fisheries.noaa.gov/inport/item/64349)
and its attribute entity [64350](https://www.fisheries.noaa.gov/inport/item/64350)) matter here:

- **`UNCERTAINTY` is a coefficient of variation.** The attribute definition (quoted in
  [Credits and use constraints](#credits-and-use-constraints)) calls it "Numerical uncertainty value
  (CV)", with `-99999` where no estimate exists. No layer here uses that sentinel. The values run from
  0.12 to 6.4, and a CV above 1 is legitimate for a sparse species.
- **`AREA_SQKM` is the true ellipsoidal area of each clipped cell.** The `source` chunk shows that it
  matches `sf::st_area()` on WGS84 to within 0.1 %. Because the 0.05° cell areas below are also
  ellipsoidal, the abundance check can be held to 1 %.

The record's abstract also lists sperm whale and a small-beaked-whale guild (*Mesoplodon* spp. and
Cuvier's beaked whale). Those surfaces are **not** in this geodatabase, which holds 13 layers.

## What this notebook does

1. Reads the 13 layers and asserts what it relies on: 12,257 cells per layer, identical geometry
   across layers, one species and one season per layer, and `ABUNDANCE = DENSITY × AREA_SQKM`.
2. Resolves each `SPECIES_2` to a WoRMS AphiaID from the pipeline's own WoRMS snapshot
   (`spp.duckdb` `worms`), with a live `worrms` cross-check when the network is available.
3. **Area-weighted regrid.** For each 0.05° cell *c*:
   $\hat d_c = \sum_p d_p\,A(p \cap c) \,/\, \sum_p A(p \cap c)$. Here $A$ is the exact overlap area in
   km², computed as the `exactextractr` coverage fraction times the cell's WGS84 ellipsoidal area,
   which depends on latitude. The same weighting gives the CV and the covered fraction of each cell.
   The rule lives in msens (`poly_cell_overlap()`, `cells_area_mean()`, msens ≥ 0.59.0), and
   `test-ingest.R` checks it against a synthetic fixture. The polygon-cell weights are computed
   **once**, because all 13 layers share the same geometry.
4. Checks every species: the regridded abundance $\sum_c \hat d_c \cdot \text{covered km}^2$ is
   within 1 % of $\sum$ `ABUNDANCE`, no output cell lies outside the source extent, and every density
   is ≥ 0.
5. Writes one 2-band Float32 COG per species (density, CV), aligned to the grid, plus the long
   Parquet and the `models.csv` model table. It writes `DONE` last.

::: {.callout-note}
## The CV band is an approximation

An area-weighted mean is right for a density, which is intensive: the regridded abundance equals the
source abundance. It is **not** right for a CV, because the CVs of the parts of a cell do not average
linearly. The CV of a mixed cell's density would need the covariance between its parts, which the
delivery does not carry. Band 2 is therefore an area-weighted average of the source CVs. It is exact
only where an output cell lies inside a single source cell, and the
[regrid section](#regrid) counts how many cells do.
:::

## Taxa → WoRMS {#taxa}

Each delivered name (`SPECIES_2`) is matched exactly against the pipeline's WoRMS snapshot. Where a
name has several WoRMS records (homonyms and synonym records), the rule picks one in this order:

1. the record that is itself **accepted**;
2. otherwise, a synonym whose accepted taxon is accepted **and in the same genus**;
3. otherwise, a synonym whose accepted taxon is accepted.

The render stops if more than one record ties at the top, or if any accepted target is not itself
accepted.

`r 13 - n_syn` of the 13 delivered names are accepted in WoRMS, and `r n_syn` are synonyms:

- ***Delphinus capensis***, the long-beaked common dolphin, is unaccepted in WoRMS and placed under
  *Delphinus delphis*. The InPort abstract itself calls this population *Delphinus delphis bairdii*,
  but WoRMS lists that subspecies as *nomen dubium*, so no accepted WoRMS taxon is specific to the CCE
  long-beaked form.
- ***Lagenorhynchus obliquidens***, the Pacific white-sided dolphin, is a junior objective synonym of
  *Sagmatias obliquidens*.

**Key choice.** `mdl_key` and the file names use the AphiaID of the name **as delivered**
(`worms_id`), not the accepted one. A raw model key identifies the source's own species, in the same
way that AquaMaps keys use its species code. Using the accepted id would collide for the two
*Delphinus* layers: `r paste(acc_dup$species, collapse = " and ")` share accepted AphiaID
`r unique(acc_dup$worms_id_accepted)`. The accepted id is kept in `worms_id_accepted`. A per-taxon
merge would fold both layers into one *D. delphis* surface, and that is a decision for whoever
promotes this dataset.

## Regrid onto the 0.05° grid {#regrid}

```{r}

```

The source's 0.1° lattice is regular, but its edges sit `r lon_off`° (longitude) and `r lat_off`°
(latitude) off the 0.05° grid lines. That is `r round(100 * abs(lon_off) / 0.05, 1)` % and
`r round(100 * abs(lat_off) / 0.05, 1)` % of a grid cell. So every other output column and every other
output row straddles a source edge. `r pct(n_single)` % of output cells lie inside a single source cell
and carry its values unchanged. In the other `r pct(n_out - n_single)` %, the largest source cell
supplies a median `r med_dom` % of the covered area, and the result is an area-weighted blend across
a sliver of the neighbour. That is harmless for the density, since the abundance is conserved (next
section). It is the approximation for the CV described in the callout above.

## Write COGs {#cog}

Each species gets one COG, `cog/cce_<worms_id>_summer-fall.tif`. Band 1 is `density`
(animals km⁻²) and band 2 is `cv`. Both are Float32 with nodata −9999 outside the modelled cells,
DEFLATE-compressed with the floating-point predictor, and in 256 × 256 blocks. There are no internal
overviews, because titiler decimates from full resolution. The window is cut from the cell-id raster
by row and column, so its origin and pixel size are the grid's own, including the ~5 × 10⁻⁶° float
drift. Each output pixel *is* a `global05` cell.

```{r}
#| label: cog

# the data window in grid rows/cols (arithmetic, row-major, 1-based, top-left origin)
ids <- as.double(cells[[1]]$cell_id)
row <- ((ids - 1) %/% grid$nc) + 1; col <- ((ids - 1) %% grid$nc) + 1
r0 <- min(row); r1 <- max(row); c0 <- min(col); c1 <- max(col)

# cut that window from the cell-id raster itself: exact grid geometry, and a lookup check for free
r_id   <- rast(cellid_tif)[r0:r1, c0:c1, drop = FALSE]
win_id <- values(r_id, mat = FALSE)
win_rc <- expand_grid(rr = r0:r1, cc = c0:c1)               # row-major, same order as values()
stopifnot("cell-id window != row-major arithmetic" =
            all(win_id == (win_rc$rr - 1) * grid$nc + win_rc$cc))
win_idx <- match(win_id, cells[[1]]$cell_id)                  # pixel -> row of cells[[l]] (NA = no data)
log_info("COG window: rows {r0}-{r1}, cols {c0}-{c1} ({nrow(r_id)} x {ncol(r_id)} px), {sum(!is.na(win_idx))} data px")

write_cog <- function(d, tx) {
  r <- rast(r_id, nlyrs = 2)
  values(r) <- cbind(d$density[win_idx], d$cv[win_idx])
  names(r)  <- c("density", "cv")
  tmp <- file_temp(ext = "tif"); on.exit(file_delete(tmp))
  writeRaster(r, tmp, datatype = "FLT4S", NAflag = -9999, overwrite = TRUE)
  # COG via gdal_translate: -stats writes real band statistics (terra's own COG path writes
  # STATISTICS_MEAN = -9999), -mo carries what a viewer needs to read the file on its own
  sf::gdal_utils("translate", tmp, path(dir_cog, tx$cog), options = c(
    "-of", "COG", "-co", "COMPRESS=DEFLATE", "-co", "PREDICTOR=YES", "-co", "BLOCKSIZE=256",
    "-co", "OVERVIEWS=NONE", "-stats",
    "-mo", glue("MDL_KEY={tx$mdl_key}"),
    "-mo", glue("SPECIES={tx$species}"),
    "-mo", glue("SCIENTIFIC_NAME={tx$scientific_name}"),
    "-mo", glue("WORMS_ID={tx$worms_id}"),
    "-mo", glue("WORMS_ID_ACCEPTED={tx$worms_id_accepted}"),
    "-mo", "SEASON=summer-fall",
    "-mo", "GRID=global05 (0.05 deg, -180..180; pixel = cell_id of r_cellid_global.tif)",
    "-mo", "BAND_1=density: animals per km2, area-weighted mean of the source 0.1 deg cells",
    "-mo", "BAND_2=cv: coefficient of variation of density, same weighting (an approximation for a CV)",
    "-mo", "SOURCE=Becker et al. 2020, NOAA-TM-NMFS-SWFSC-638, https://doi.org/10.25923/3znq-yx13",
    "-mo", "INPORT=https://www.fisheries.noaa.gov/inport/item/64349"))
  invisible(path(dir_cog, tx$cog))
}
walk(seq_len(nrow(taxa)), \(i) write_cog(cells[[taxa$layer[i]]], taxa[i, ]))

kable(cog_chk, digits = 9, format.args = list(big.mark = ","),
```
