Marine Sensitivity Toolkit · plan for review · 2026-09-20

Atlas: one static app for scores, species, places and reports

A browser-only replacement for the two R Shiny apps and the Quarto report API. Static files on GitHub Pages read the published marine-atlas release straight from cloud storage; restricted pre-releases (v8 and v9 today) are served by the same build behind Cloudflare Access. Nothing is built yet. This page is the plan, the evidence it rests on, and a first look at the interface in the Marine Minerals Administration visual language.

Look and feel

The map is the page. Everything else floats above it and folds away: a slim bar, a honeycomb rail of icon buttons, glass panels that collapse to pills, and text kept to one line until someone asks for more. The mockups are live HTML, CSS and canvas drawn with the tokens the app would ship: the four MMA colors, the guide's two typefaces with open fallbacks, and the hexagon and wave motifs held to the guide's 10 % opacity.

What is real here: the Program Area outlines and every number in the Scores panel (published v7 values), the Rice's whale record and its input layers (v9 metadata), the coastline (Natural Earth). What is a stand-in: the two colored surfaces, which are synthetic, and the basemap, which the app draws with MapLibre. The MMA seal is deliberately absent (decision D10).

Architecture

Svelte 5 + Vite, no router

Cloudflare Access scopes a reviewer policy by path, never by query, so one build must run under /atlas/ and under /v9/atlas/. Assets are base-relative and all view state is query plus hash. SvelteKit's router binds to one base path, and nothing here needs server rendering. Two HTML entries cover the "routes": the map and the report.

Normalize at publish

msens::app_bundle_build() writes {ver}/app/ with one schema for v1 through v9: a first-paint bundle, a species index, 256 per-taxon shards with precomputed camera boxes, normalized species-by-zone and taxon tables, and wide cell tiles. The legacy quirks stay in R, under the tests that already guard them.

The link is the analysis input

Places ride in the hash in a small binary codec (delta and zigzag varints, base64url, about 4 to 5 characters per vertex at 0.001°). Every analysis runs on the decoded geometry, so a shared link reproduces its numbers exactly. msens gets the R twin, so a link can be read in R too.

OPFS, if and only if it helps

The persistent database holds the small tables and a least-recently-used set of tiles, capped at 300 MB or 20 % of quota. One tab holds the file; every other tab, private windows and every failure fall back to memory. The npm latest build of DuckDB-WASM creates OPFS files and never writes them; spike S1 pins a version that does.

Preview access for v8 and v9

The same commit of the same build is served twice. GitHub Pages renders public releases only. The preview host serves the identical files under each version's path, behind Cloudflare Access and the origin's token check, exactly where the Shiny previews live today.

What the surveys turned up

Four surveys were run before writing the plan: both Shiny apps read in full, the report pipeline traced end to end, and the CalCOFI Explorer reviewed as the precedent. They are kept beside the plan as the specification. Every number below was re-checked against the live bucket on 2026-09-20.

3 formulas, 1 area

Beyond the gap above, cells_in_pra() hardcodes 100 % coverage although 74,938 of 2,241,876 zone cells are partial, and the report's CSV link derives a third cell set from a GeoPackage. The plan fixes these in msens with named regression tests instead of porting them. The acceptance test: trace a Program Area, get its published score.

72 MB per click

cell_metric.parquet has three row groups, each spanning every cell and every metric, so nothing can be pruned: one clicked cell would download the whole file. The plan publishes wide cell tiles on the 2.5° key the species tiles already use, about 110 to 250 KB each.

757 MB missing for v7

The per-cell species tiles are on S3 and readable for v8 and v9, but absent for v7, the public release, although its manifest advertises the capability. The manifest describes the server's tables, not what a static client can reach; the new app block derives capabilities from anonymous HTTPS checks.

0 SQL for species

Once camera boxes and asset lists are precomputed per taxon, the species lens needs no database at all. That retires the app's most expensive query (a min/max over a whole model joined to a 17-million-row table) and the 86,857-row asset lookup.

4 bugs not to port

A layers control wired to layer ids that no longer exist; a flower-plot default shared across every release; a grey "primary producer" petal; hard-coded global grid constants in the species click, which are wrong for v1 through v7.

301 that looks like 200

The bucket is in us-east-1 and needs path-style URLs. The other spelling answers 301 with an XML body that curl -sf accepts. Anonymous listing is denied, so every object key must be constructible. Both are now gates, each with a seeded fault that must turn it red.

Decisions

Four are settled (green). Two still wait on you: report formats (D9) and brand approvals (D10). Work proceeds on the recommendation unless a subplan says stop.

D7 ✓

One scoring method: decided, harmonize with Program Areas

Custom places use the published zone method, Σ(coalesce(val,0)·pct) / Σ(pct), including pct_covered for partly covered edge cells. You confirmed the meaning, "absent means zero, inside the study area", and that drawn-polygon numbers may change from old reports. It is fixed in msens with regression tests, and the acceptance test is a polygon traced around a Program Area reproducing its published score.

Why it matters: turtles occur in 297 of St. George Basin's 16,850 cells. The published turtle score for the area is 0.7; a polygon traced around it reports 49.8 today, and 32.9 overall against the published 26.7. The panel will show all three numbers: the score, the coverage (1.4 %) and the mean where present (49.8).

D7b, decided: clip custom places to US waters. One cell set per place, the touched cells inside the study area, drives scores, species, area and cell counts, so land and foreign waters never enter as zeros. Measured on v9, this moves a traced Program Area's composite by at most 0.08 points, so it still reproduces its published score. The panel and the report state what share of the place is inside the study area.

D6 ✓

The review gate: decided, presentation gate now, protect the data later

The public host renders public releases only. The preview host serves the same build per version path behind Cloudflare Access and the origin's token check, and the same-origin session.json that exists only there is the sole way into preview mode. Screens and reports from a restricted release are watermarked.

The files of v8 and v9 stay on the public bucket for now, as they are today. Protecting them from direct reading is a committed follow-up with two routes, both configuration for the app because it forms its data address in one function that prefers a value supplied by session.json:

  • Unguessable addresses. Publish a restricted release under a random prefix that only the signed-in preview host reveals. Listing the bucket is already denied, so it cannot be discovered; tiles keep working unchanged.
  • Private data. Restricted files leave the public bucket and are served only through the preview host, tiles included. Real confidentiality, at the cost of a private tile route and server bandwidth.
D1 ✓

Name and address: decided, atlas

Repo MarineSensitivity/atlas; public at marinesensitivity.org/atlas/ (project Pages under the organization's existing domain, no DNS work); preview at preview.marinesensitivity.org/{ver}/atlas/. Decided 2026-09-20.

D9

Report formats

Print-first HTML (the browser's "Save as PDF": real, selectable text and no LaTeX), a self-contained HTML download and a ZIP data package. Today's Word output has no reference template at all.

Recommended: build Word only if the API's report log shows it is used. Needs: do BOEM colleagues rely on .docx?

D10

Brand approvals

Palette, type and motifs now; seal and agency name behind build flags, off until the Office of Communication approves through the COR. The guide spells the agency two ways ("Minerals" on the seal, "Mineral" in the text). The branding folder also holds an unexplained "Offshore Hub" wordmark.

Recommended: ask once for all three. Needs: who asks, and whether Offshore Hub is a portal to link to.

DuckDB-WASM on OPFS is young

Development-tagged builds and a write bug on the default tag. Pinned by a spike, feature-detected, never required: the in-memory path is the default and the tested one.

The tile server stays

If it is down the rasters go blank while zones, scores, tables, places and reports keep working from S3. A spike measures client-side rendering as the way out.

Phones and big places

A 40-tile place is about 30 million rows. Batched aggregation, a fetch plan the user confirms, and a tile cache keep it bounded.

A published number changes

Drawn-polygon scores move by up to 6.3 points on the composite (0.5 at the median). That is the fix; the Program-Area-tracing test is what makes it defensible.
