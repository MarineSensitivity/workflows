# atlas-8 · Verification, Section 508, performance: the gates that let the old apps retire

**Phase:** A8 of `2026-09-20 atlas app plan.md` (after atlas-4…7; its harness starts in atlas-0 and
grows with every phase, this phase completes and audits it). **Model:** Sonnet writes specs and fixes;
Opus audits every gate for "can this check fail?", does the manual accessibility walk, and writes the
sign-off; no Fable. **Touches:** `../atlas/{tests,e2e,scripts}/**`, `docs/parity.html` (generated),
`.github/workflows/*.yml`.

## Why this phase exists
The recurring failure in this project is verification that passes on broken input: `curl -sf` on an S3
301, a probe counting the wrong thing, a manifest advertising a table the client cannot reach, a merge
hash that structurally could not see the surface the app draws. A static app multiplies the places
that can go quietly wrong (a blank WebGL canvas has a perfectly healthy DOM). So every gate below
carries a **seeded fault** it must catch, committed next to it.

## The pyramid
| layer | proves | seeded fault it must catch |
|---|---|---|
| Vitest, rules | codec, coverage, grid, URL round-trip, ramps wiring, release gating, report model | `Math.round` for half-even; `nc = 7200` on `usa05`; a legend importing its own ramp; `access` missing → treated as public |
| Parity, Node (`scripts/parity/run.mjs`) | the app's own `sql/*.sql` equals msens on v7 and v9 (`max|Δ| < 1e-9`) | `blend` off; `value` for `val`; join on `metric_seq` after a re-registered `metric` table |
| Playwright state matrix (`scripts/verify.mjs`) | ~120 named URLs × desktop 1280×800 / phone 390×844 × Chromium, WebKit, Firefox: layout (no overflow, controls on screen), per-state assertions, **`gl.readPixels` probes at known lon/lat** | raster source 404 (DOM still fine); `setStyle` losing the zone layer; panel off-screen at 390 px |
| First paint | default view and a species deep link complete with `**/*.wasm` and `**/duckdb*` blocked | DuckDB statically imported; a lens awaiting the engine before drawing |
| Persistence | OPFS reload with S3 blocked; second tab; private window; corrupted file; "don't keep data" | the dev57 no-write bug; a missing `CHECKPOINT` (kill the page right after the write) |
| Privacy | the hash in no request, no analytics payload, no error report, across the whole matrix | a place put in the query; `page_location = location.href` |
| Preview gate | public host renders no restricted release and requests nothing under `/{restricted ver}/`; preview host needs Access (atlas-9's curl proofs) | `?ver=v9` honoured on Pages; `session.json` faked via `localStorage` |
| Accessibility | axe (zero serious/critical) on every matrix state + the gallery + the report; scripted keyboard walk: select a Program Area, read its scores from the zones table, create a place by coordinates, open and export the report, all without a pointer | a hex button without a name; focus lost after a modal closes |
| Smoke on the deployed site (`scripts/smoke_release.mjs`) | the live build reads the promoted release; lists every failed request and console error | path-style vs virtual-host S3 URL; a stale `latest.txt` cache |

WebGL in CI: Chromium with SwiftShader is enough for pixel probes; run the matrix once per release
candidate on a real headed Chrome too (`atlas-refs/calcofi explore review.md` lesson 9).

## Deliverables
1. The completed matrix, the seeded-fault suite (`npm run test:faults` flips each fault and expects red),
   the budgets wired into CI, cross-browser runs.
2. **`docs/parity.html`** — generated from the checklists of atlas-4, -5, -7: every line with its
   assertion id, status, and a screenshot pair (Shiny vs Atlas at the same state, taken by
   `scripts/shots.mjs` against `app.marinesensitivity.org` and the Pages site). This page is what Ben
   signs; atlas-9's cutover is gated on it.
3. A **Section 508 conformance note** (`docs/accessibility.md`): WCAG 2.1 AA criteria, how each is met,
   known exceptions (the map canvas itself; its equivalent is the zones table), test evidence.
4. **Beta feedback**: "Report a problem" opens a prefilled GitHub issue in `MarineSensitivity/atlas`
   (app SHA, release, lens, the URL **without the hash**, user agent); no backend (the CalCOFI
   zero-backend fallback). A `VITE_FEEDBACK_URL` Apps Script endpoint can be added later.
5. Performance notes: what was measured, on what, and the three slowest states with their cause.
