# Plan: v8 "Marine Atlas" — global 0.05° raster (rolled back from H3 hex), targets/metadata pipeline, partitioned Parquet on S3, stable `mdl_key`

## Context

An earlier iteration of this plan made **H3 res-7 hexagons** the core spatial unit. That is now being
**rolled back**: interpolating every SDM onto ~70M global hexes is a ~4-day job, and the realities of the data
argue for staying on a raster grid — the next-round primary provider **AquaX is already native 0.05° raster**
(>10k TIFs at `~/_big/msens/AquaX_2026-04/SDM/MBON_USA_BOEM_masked_emmean_matched_species_TIF_TIF/`), and
AquaMaps is native 0.5° that resamples cheaply to 0.05° (bilinear), so a raster pipeline is both faster and a
better fit.

**v8 therefore uses a global 0.05° raster cell grid in [-180,180]** (not the v7 US-only, 0-360 grid), keeping
everything else the pivot was meant to deliver:
- **Global species ingest** (worldwide distributions → range-size / endemism / rarity), **US-only scoring**.
- All the **pipeline improvements**: `targets` driven by `msens:` qmd metadata, the **partitioned-Parquet
  marine-atlas release on S3** (`s3://oceanmetrics.io-public/marine-atlas/`), the **validation-first** v7↔v8
  score-equivalence gate, growing reusable logic into **`msens`**, splitting the oversized notebooks, and the
  `workflows/CLAUDE.md` rewrite + `.claude/skills/`.
- The H3 helper functions (`msens/R/hex.R`, `msens/R/interp.R`) are **kept but dormant** — not in the v8
  pipeline, retained for future H3 work (they are documented + tested).
- The species mapper (`apps/mapsp`) shows the **original dataset model** (native PMTiles/COG) **and** the
  **converted 0.05° raster** side-by-side — so each source model is published in its native format + registered
  in STAC (Phase 4b), and `mapsp` is re-rendered through **titiler** like `apps/mapgl` (its current mapboxgl +
  in-R terra path won't scale to global rasters).
- The v8 grid is anchored to the **shared 0.05° [-180,180] topology of Bio-Oracle AND AquaX** (verified aligned),
  so AquaX (next round) ingests with **no projection**.

Two more decisions the user set with this pivot:
- **Stable `mdl_key` replaces auto-increment `mdl_seq`.** The old sequence re-numbered on every rebuild and
  dropped the prior id, breaking the model-revisit URLs (apps/titiler key on it) across versions.
- **`am`** is the AquaMaps `dataset_key` (not `am_0.05`), and AquaMaps is **reingested globally** from
  `am.duckdb`, **parallelized** (`furrr`).

## `mdl_key` scheme (locked with the user)
`mdl_key = {dataset_key}|{sp_id}[|{interval}]` — **pipe `|` separator** (dash `-` occurs inside AquaMaps
sp_keys), dataset first.
- **Raw per-dataset models** use the **dataset-native** species/guild id (nc has multi-species *guilds* not
  resolvable to one worms_id, which is why raw stays native): `am|Fis-29291`, `bl|<botw_handle>`,
  `gm|<sefsc_id>|01` (month `01`..`12`), `nc|<guild_id>|summer` (season name).
- **Merged `ms_merge`** uses the taxon id with a **taxadb prefix**: `ms_merge|WORMS:137209`,
  `ms_merge|BOTW:22694927` (also `ITIS:`/`GBIF:`/`SLB:` available for crosswalking).
- Raw↔merged linkage stays in `taxon_model` (taxon_id ↔ each dataset model). `mdl_seq` may remain an internal
  surrogate, but the **stable public identifier and all URLs use `mdl_key`**.

## Already done (KEEP — grid-agnostic) vs rolled back
- **KEEP (committed):** `msens/R/workflow.R` targets generator + `_targets.R`; `msens:` metadata blocks on the
  pipeline notebooks; `paths.R` `ver="v8"` + `s3_atlas`; `msens/R/validate.R` (v7↔v8 PRA equivalence) + tests;
  the msens-buildout pattern. All independent of hex vs cell.
- **ROLL BACK:** `build_hex_grid.qmd` → `build_cell_grid.qmd` (and the `msens:` `build_hex_grid` dependency →
  `build_cell_grid`); the `ingest_aquamaps_res05.qmd` `v8_hex_ingest` chunk → a cell-based ingest; the built
  global `hex`/`hex_src_w` tables in `~/_big/.../v8/sdm.duckdb` (superseded by the `cell` grid).
- **KEEP DORMANT:** `msens/R/hex.R`, `msens/R/interp.R` — add a header note "not used by the v8 pipeline;
  retained for future H3 work"; leave their tests.

## Phase 1 — Global 0.05° cell grid ([-180,180], AquaX-aligned topology)
**Files:** new `workflows/build_cell_grid.qmd` (`workflow_type: grid`); `msens/R/calc.R` (global-grid variants);
retire `build_hex_grid.qmd`.
- **Grid topology = the shared 0.05° [-180,180], 3600×7200, EPSG:4326 grid** — verified that Bio-Oracle v3 AND
  the AquaX TIFs are already on exactly this grid (same extent/res/dim/origin). Anchoring the v8 grid to it means
  **AquaX ingests need no projection/resample — direct `cell_id` extraction** (values 0-1000).
- Build the **global** ocean grid from Bio-Oracle v3 (`bio_oracle_tif`) — like v7's `create_grid`
  (`ingest_aquamaps_to_sdm_duckdb.qmd`) but **global and NOT rotated to 0-360**. `cell_id = 1:ncell` over ocean
  (depth_mean non-NA); write a **global cell-id COG in [-180,180]** (`r_cellid_global.tif`) + the `cell` table:
  `cell_id`, the 12 Bio-Oracle env layers, `area_km2` (`terra::cellSize`), and boolean `in_usa` (within
  `ply_boem-usa.gpkg`) / `in_pra` (within `ply_programareas_2026`).
- Update `msens::cell_id_raster()`/`cells_in_polygon()` for the **global [-180,180]** COG (drop the
  `st_shift_longitude` 0-360 handling for the v8 grid). US cells are the `in_usa` subset.

**Verify:** global ocean cell count (~17M order, cf. Bio-Oracle 17,072,105 ocean pixels); `sum(in_usa)` ≈ v7's
661k order; COG bounds report [-180,-90,180,90]; a known lon/lat → expected `cell_id`.

## Phase 2 — `mdl_key` schema
**Files:** `workflows/schema.qmd`, `create_sdm-tables.qmd`, `merge_models*.qmd`, `calc_scores.qmd` (all readers
of `mdl_seq`), `msens/R/stac.R` + apps/api (URL keys).
- Add `mdl_key VARCHAR` as the **stable model identifier** on `model` (unique), carried on `model_cell`
  (`mdl_key, cell_id, value`), `taxon`, `taxon_model`, `zone_taxon`. Keep `mdl_seq` only as an optional internal

- Compose per the scheme above. Provide `msens` helpers: `mdl_key_raw(dataset_key, sp_id, interval=NULL)` and
  `mdl_key_merged(taxon_authority, taxon_id)` (taxadb prefix), so all notebooks build keys one way.

## Phase 3 — AquaMaps global reingest (parallelized) → partitioned Parquet
**Files:** **rename `ingest_aquamaps_res05.qmd` → `ingest_aquamaps.qmd`** (supersede/archive the existing 248-line
`ingest_aquamaps.qmd`), `msens:` `ds_key: am`.
- Source: **`am.duckdb`** (`~/_big/msens/derived/aquamaps/am.duckdb` laptop, `/share/data/derived/aquamaps/am.duckdb`
  server) — `spp` (23,699 species: sp_key, genus/species, iucn), `cells` (177,869 HCAF 0.5° global), `spp_cells`
  (118M rows: sp_key, probability, cell_id). Global extent confirmed ([-179.8,179.8]).
- Per species: rasterize its `spp_cells` probabilities onto the HCAF 0.5° grid (or read the cached
  `raw/aquamaps.org/spp_cells/{sp_key}.tif`, 1-100), **zero-fill absent cells then bilinear-resample onto the
  global 0.05° grid, mask to ocean, 0→NA** (the proven v7 `iterate`/`resample_smooth` fade —
  `ingest_aquamaps_res05.qmd:205-219`), extract `(cell_id, value)`, stamp `mdl_key = "am|{sp_key}"`, write one
  partitioned Parquet per species → `marine-atlas/{ver}/dist/dataset=am/mdl_key=.../part.parquet`.
- **Parallelize with `furrr`** (`future::plan(multisession, workers=…)`, `furrr::future_map`): one am.duckdb
  read-only connection + one output partition per worker (no shared writes). **Resumable** — skip species whose
  partition exists. Write `dataset`(ds_key='am') + `model`(mdl_key, taxa=sp_key, ...) rows.

**Verify:** N species partitions; a species' global 0.05° surface renders worldwide; interpolated values ⊂ source
[1,100] with a clean ~cell-scale edge fade (no bleed); a US species matches its v7 0.05° surface closely.

## Phase 4b — Native-format original-model publishing (→ STAC + S3) for original-vs-converted overlay
**Files:** each `ingest_*.qmd` (native-publish step); new `msens/R/publish.R` (`publish_pmtiles()`,
`publish_cog()`); `msens/R/stac.R`.
- So the species mapper (`apps/mapsp`) can show BOTH the **original dataset model** and the **converted 0.05°
  raster**, each ingest publishes its source model in its **native cloud-native format** to the marine-atlas S3
  tree and registers it in the **STAC** catalog (sdm extension):
  - vector sources (IUCN/BOTW/FWS/NMFS ranges) → **PMTiles** (tippecanoe)
  - raster sources (AquaMaps native 0.5°, **AquaX 0.05°** — identical to the converted for AquaX, NCCOS) → **COG**
- Each STAC Item carries the **native asset (PMTiles/COG)** + the **converted asset** (0.05° `model_cell`
  Parquet + titiler-SQL link), keyed by `mdl_key`, so the mapper overlays original vs converted. (This restores
  the native-publishing goal from the pre-pivot plan, now on the 0.05° grid.)

## Risks / watch-items
- **`mdl_key` is pipeline-wide** — every `mdl_seq` reader (merge, score, stac, apps, api) must switch; do it as
  one coherent schema change (Phase 2) before the ingests write.
- **Grid-change comparability**: 0.05° stays, but US→global + 0-360→[-180,180] renumbers `cell_id` and can nudge
  ecoregion min/max — the `validate_v7_v8` PRA delta is the guardrail (expect near-zero).
- **Global volume**: global 0.05° merged distributions are large even as Parquet — partition per `mdl_key`,
  measure on the AquaMaps prototype.
- **furrr + DuckDB**: connections are not fork-safe — open one read-only con per worker; never share a write
  target; keep the loop resumable.
- **Longitude [-180,180]** applied consistently on the new grid + COG + `msens/R/calc.R`.
